# 缓存层次结构

CPU 每秒可以执行数十亿条指令。主存（DRAM）响应一次请求大约需要 200 个 CPU 周期。没有缓存时，CPU 大部分时间都在等待数据。

解决方案是 **存储层次结构**：把存储按速度、容量和成本分成多层，越靠近 CPU 的层越快、越小、越贵。

## 交互式可视化

点击任意层级查看参数。输入一个地址并点击 **Access Memory**，即可模拟该请求由哪一层命中。

## 为什么需要多级缓存？

这里存在明确的物理权衡：

- **更快** 的存储 -> 容量更小、成本更高、功耗更大
- **更大** 的容量 -> 访问更慢、单位比特更便宜

| 层级 | 典型容量 | 延迟 | 说明 |
|------|---------|------|------|
| 寄存器 | 约 1 KB | < 1 ns | 有名字；不可按地址访问 |
| L1 缓存 | 32-64 KB | 1-4 周期 | 指令/数据分离；每核私有 |
| L2 缓存 | 256 KB - 1 MB | 10-15 周期 | 统一缓存；每核私有 |
| L3 缓存 | 4-32 MB | 30-50 周期 | 全核共享 |
| DRAM | 8-64 GB | 200+ 周期 | 片外 |
| NVMe SSD | 256 GB - 4 TB | 约 100,000 周期 | 持久化存储 |

## 核心概念

### 命中与未命中

- **缓存命中（hit）**：请求数据在当前缓存中 -> 以缓存速度返回
- **缓存未命中（miss）**：数据不在当前缓存中 -> 向下一层取数（填充缓存行后再重试）

### 平均访存时间（AMAT）

$$AMAT = HitTime + MissRate \times MissPenalty$$

若 L1 命中时间为 4 周期、未命中率为 5%、L2 访问时间为 12 周期：

```txt
AMAT = 4 + 0.05 x 12 = 4.6 cycles
```

如果 L2 也未命中并下探到 DRAM（200 周期），惩罚会显著增大。

### 缓存行（Cache Line）

缓存不是按单字节存储，而是按 **缓存行**（通常 64 字节）存储。发生未命中时，会把整块 64 字节搬入缓存，这利用了 **空间局部性**。

### 局部性

缓存之所以有效，是因为程序通常具有 **局部性**：

| 类型 | 定义 | 示例 |
|------|------|------|
| **时间局部性** | 最近访问过的数据很可能很快再次访问 | 每次循环都访问的计数器 |
| **空间局部性** | 靠近刚访问地址的数据很可能很快被访问 | 顺序遍历数组 |

### 缓存组织

缓存通常按 **组（set）** 划分，每组有 **N 路（ways）**：

- **直接映射（1-way）**：每个地址只能映射到一个槽位。查找快，但容易冲突未命中。
- **N 路组相联**：地址可落在该组的任意一路。命中率更高，但比较电路更复杂。
- **全相联**：任意块可放在任意位置。常见于 TLB，不适合大容量缓存。

### 替换策略

当某组已满且需要装入新块时：
- **LRU（最近最少使用）**：淘汰最久未访问块。最接近最优策略。
- **FIFO**：淘汰最早进入的块。实现简单。
- **Random**：随机淘汰。效果常常接近 LRU，硬件成本低，部分 ARM 设计会采用。

## 性能影响

:::tip 编写缓存友好代码
```c
// BAD：按列遍历 -> 每次访问几乎都可能触发缓存未命中
for (int j = 0; j < N; j++)
    for (int i = 0; i < N; i++)
        sum += A[i][j];

// GOOD：按行遍历 -> 每个缓存行可复用多次（64B / 8B = 8 个 double）
for (int i = 0; i < N; i++)
    for (int j = 0; j < N; j++)
        sum += A[i][j];
```

对于 1024x1024 的 double 矩阵，仅因 L1 命中率差异，按行遍历通常可达到约 **5x** 提速。
:::
