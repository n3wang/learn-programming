## 1. Auto-configuration

Boot **guesses** what you need from the classpath and properties, then registers beans — unless you already defined them. Example: `spring-boot-starter-web` → embedded Tomcat. Prefer Jetty? Exclude Tomcat and add the Jetty starter; Boot **backs off**.

```xml
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-web</artifactId>
  <exclusions>
    <exclusion>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-tomcat</artifactId> <!-- drop default server -->
    </exclusion>
  </exclusions>
</dependency>
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-jetty</artifactId> <!-- use Jetty instead -->
</dependency>
```

### Motivation: shared configs and opting out

Teams often extract shared `@Configuration` beans into a library and `@Import` them. That breaks when one consumer needs **most** beans but not one of them (e.g. no relational `DataSource`). Spring’s `@Conditional` (and Boot’s specialized variants) gate bean creation on classpath, properties, or existing beans.

### `@Conditional`

Place `@Conditional(MyCondition.class)` on `@Bean` / `@Component` / `@Configuration`. Implement `Condition.matches(...)` — `true` → create; `false` → skip. Typical checks: class present on classpath, or a property set via `ConditionContext`.

### Boot’s high-level conditionals

| Annotation | True when… |
|---|---|
| `@ConditionalOnClass` | Named class is on the classpath |
| `@ConditionalOnMissingBean` | No bean of that type already exists |
| `@ConditionalOnBean` | A bean of that type exists |
| `@ConditionalOnProperty` | Property is present / matches |
| `@ConditionalOnWebApplication` | App is a web app |
| `@ConditionalOnMissingClass` | Class is **not** on the classpath |

These power auto-config: e.g. create a pooled `DataSource` only if the classes exist **and** you did not define one yourself (`@ConditionalOnMissingBean`).

```java
@Bean
@ConditionalOnMissingBean(DataSource.class) // only if user did not define one
@ConditionalOnClass(DataSource.class)
public DataSource dataSource() { … }
```

### Deep dive: `DataSourceAutoConfiguration` (idea)

Boot’s JDBC auto-config is a `@Configuration` that roughly:

1. `@ConditionalOnClass({ DataSource.class, EmbeddedDatabaseType.class })`
2. `@EnableConfigurationProperties(DataSourceProperties.class)` for `spring.datasource.*`
3. Nested configs for **embedded** vs **pooled** datasources, each with `@ConditionalOnMissingBean({ DataSource.class, XADataSource.class })`
4. Imports Hikari / Tomcat / DBCP2 configuration classes when the pool condition matches

Same pattern everywhere: **classpath + missing user bean ⇒ Boot supplies a default**.

Registration: older Boot listed auto-configs under `EnableAutoConfiguration` in `META-INF/spring.factories`. Boot 3 prefers `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`.

```xml
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-web</artifactId>
  <exclusions>
    <exclusion>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-tomcat</artifactId>
    </exclusion>
  </exclusions>
</dependency>
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-jetty</artifactId>
</dependency>
```

## 2. DevTools

```xml
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-devtools</artifactId>
  <optional>true</optional> <!-- do not leak to dependents -->
</dependency>
```

DevTools (development only):

- **Property defaults** — turns off caches that hurt local edit/refresh (templates, etc.)
- **Automatic restart** — classpath changes reload app code via a restart classloader (third-party jars stay in a base loader)
- **LiveReload** — browser refresh when static resources change (browser extension required)

```xml
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-devtools</artifactId>
  <optional>true</optional>
</dependency>
```

## 3. Custom FailureAnalyzer

Boot formats startup failures (e.g. port in use) via `FailureAnalyzer`. You can plug in domain checks:

1. Throw a custom exception (e.g. `UrlNotAccessibleException`)
2. Extend `AbstractFailureAnalyzer<YourException>` and return `FailureAnalysis(description, action, cause)`
3. Register in `META-INF/spring.factories` (or Boot 3 imports) under `org.springframework.boot.diagnostics.FailureAnalyzer`
4. Trigger validation on a lifecycle event (`ContextRefreshedEvent`, etc.)

```java
public class UrlNotAccessibleFailureAnalyzer
    extends AbstractFailureAnalyzer<UrlNotAccessibleException> {
    @Override
    protected FailureAnalysis analyze(Throwable root, UrlNotAccessibleException cause) {
        return new FailureAnalysis(
            "Unable to access the URL " + cause.getUrl(), // what failed
            "Validate the URL and ensure it is accessible", // what to do
            cause);
    }
}
```

```properties
org.springframework.boot.diagnostics.FailureAnalyzer=\
com.example.demo.UrlNotAccessibleFailureAnalyzer
```

```java
public class UrlNotAccessibleFailureAnalyzer
        extends AbstractFailureAnalyzer<UrlNotAccessibleException> {
    @Override
    protected FailureAnalysis analyze(Throwable rootFailure, UrlNotAccessibleException cause) {
        return new FailureAnalysis(
            "Unable to access the URL " + cause.getUrl(),
            "Validate the URL and ensure it is accessible",
            cause);
    }
}
```

## 4. Spring Boot Actuator

### Enable

```xml
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>
```

Brings actuator auto-config + **Micrometer** for metrics. Discovery page: `/actuator`. Default HTTP exposure is mainly **`health`** and **`info`**; many other IDs are on JMX by default.

### Common endpoints

| Id | Purpose |
|---|---|
| `health` | Aggregated / component health |
| `info` | App info from properties / contributors |
| `metrics` | Micrometer meters |
| `env`, `beans`, `conditions` | Environment, beans, auto-config report |
| `loggers`, `threaddump`, `heapdump` | Ops diagnostics |
| `shutdown` | Stop the app (disabled by default) |

Expose over HTTP:

```properties
management.endpoints.web.exposure.include=health,info,metrics
# or * then exclude sensitive ones
management.endpoints.web.exposure.exclude=shutdown,heapdump
management.endpoints.web.base-path=/actuator
management.server.port=8081 # optional separate management port
```

```xml
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>
```

### Health deep dive

Statuses: `UP`, `DOWN`, `OUT_OF_SERVICE`, `UNKNOWN` (custom via `Health.status("FATAL")`). Aggregation uses priority (DOWN wins by default). Map statuses to HTTP codes with `management.endpoint.health.status.http-mapping.*`.

Built-in indicators: disk space, ping; **DataSource** appears when JDBC is on the classpath.

**Custom `HealthIndicator`:** `@Component` class implementing `health()` → `Health.up()` / `down()`, optionally `withDetails` / `withException`. Convention: name ends with `HealthIndicator`.

```java
@Component
public class DogsApiHealthIndicator implements HealthIndicator {
    @Override
    public Health health() {
        // call remote API; return Health.up() or Health.down()
        return Health.up().withDetail("api", "reachable").build();
    }
}
```

```java
@Component
public class DogsApiHealthIndicator implements HealthIndicator {
    @Override
    public Health health() {
        return Health.up().withDetail("api", "reachable").build();
    }
}
```

### Info deep dive

Default `/info` is empty. Fill it with:

- `info.*` properties in `application.properties`
- Maven/`@project.*@` expansion or `build-info` goal → `build-info.properties`
- `git.properties` via git-commit-id plugin
- Custom `InfoContributor` `@Component` implementing `contribute(Info.Builder)`

```properties
info.app.name=Course Tracker
info.app.version=1.0.0
```

```java
@Component
public class CourseInfoContributor implements InfoContributor {
    @Override
    public void contribute(Info.Builder builder) {
        builder.withDetail("courses", List.of()); // attach custom payload
    }
}
```

### Custom actuator endpoint

```java
@Component
@Endpoint(id = "courses") // appears as /actuator/courses when exposed
public class CourseEndpoint {
    @ReadOperation
    public Iterable<Course> courses() { … }

    @WriteOperation
    public void updateRating(@Selector Long id, int newRating) { … }

    @DeleteOperation
    public void deleteAll() { … }
}
```

Expose with `management.endpoints.web.exposure.include=courses` (or `*`). Prefer not to put core business mutations only on Actuator in production — use REST APIs; Actuator is for ops.

### Metrics (Micrometer)

`/actuator/metrics` lists meters; `/actuator/metrics/{name}` shows one. Custom meters: **Counter**, **Gauge**, **Timer**, **DistributionSummary** registered on `MeterRegistry`. Export to Prometheus with `micrometer-registry-prometheus` → `/actuator/prometheus`; visualize in Grafana.

```java
@Bean
public Counter createCourseCounter(MeterRegistry registry) {
    return Counter.builder("api.courses.created.count") // metric name
        .description("Total number of courses created")
        .register(registry);
}
```

```java
@Bean
public Counter createCourseCounter(MeterRegistry meterRegistry) {
    return Counter.builder("api.courses.created.count")
        .description("Total number of courses created")
        .register(meterRegistry);
}
```
