## 1. Spring MVC and the front controller

**MVC** splits UI apps into:

| Piece | Role |
|---|---|
| Model | Data for the view |
| View | Renders HTML (here: Thymeleaf) |
| Controller | Handles HTTP, calls services, fills the model, returns a **logical view name** |

Spring MVC sits on the IoC container. All requests go through a **front controller**: the **`DispatcherServlet`**. It does not do all work itself — it delegates.

Simplified flow:

1. Request hits `DispatcherServlet`
2. **`HandlerMapping`** finds a controller/handler
3. **`HandlerAdapter`** invokes it
4. Controller runs business logic, builds a **model**, returns a view name
5. **`ViewResolver`** maps name → real view (e.g. `index` → `templates/index.html`)
6. View renders model data to the response

Other collaborators:

- **`LocaleResolver`** — client locale (default often `AcceptHeaderLocaleResolver`)
- **`HandlerExceptionResolver`** — map errors to error views / status (or pass along)

In Boot web apps, `DispatcherServlet` is auto-configured; you rarely write `web.xml` by hand.

```java
@Controller
public class CourseController {

  @GetMapping("/index")
  public String index(Model model) {
    model.addAttribute("courses", courseService.findAllCourses()); // key → view
    return "index"; // logical view → templates/index.html
  }
}
```

## 2. Thymeleaf overview

**Thymeleaf** is a server-side template engine (HTML, XML, TEXT, JS, CSS, RAW). HTML templates mix normal HTML with `th:*` attributes. The engine replaces them with data from the Spring **model**, then sends plain HTML to the browser.

Declare the namespace:

```html
<html xmlns:th="http://www.thymeleaf.org">
```

Boot: add `spring-boot-starter-thymeleaf` and put templates in `src/main/resources/templates/`.

Two common web styles with Boot:

1. **SPA frontend** (React/Angular/Vue) + Boot **REST** JSON API  
2. **MVC + template engine** (Thymeleaf) — same app serves HTML views  

This lesson focuses on (2).

## 3. Displaying model attributes

Controller:

```java
@GetMapping
public String getLoggedInUserName(Model model) {
  model.addAttribute("userName", user.getName());
  return "index";
}
```

Template:

```html
Logged in user: <span th:text="${userName}"></span> <!-- ${key} from model -->
```

Iterate a list:

```html
<tr th:each="course : ${courses}">
  <td th:text="${course.id}"></td>
  <td th:text="${course.name}"></td>
  <td th:text="${course.description}"></td>
</tr>
```

```html
<html xmlns:th="http://www.thymeleaf.org">
<body>
  <span><!-- show userName --></span>
  <table>
    <tbody>
      <!-- each course row -->
    </tbody>
  </table>
</body>
</html>
```

## 4. Conditionals

```html
<span th:if="${author.gender} == 'M'" th:text="Male"></span>
<span th:unless="${author.gender} == 'M'" th:text="Female"></span>
```

Switch / case:

```html
<div th:switch="${course.category}">
  <div th:case="'Spring'"><h2>Spring Course</h2></div>
  <div th:case="'Python'"><h2>Python Course</h2></div>
  <div th:case="*"><h2>Some other course</h2></div> <!-- default -->
</div>
```

```html
<td>
  <!-- Male if gender == 'M', else Female -->
</td>
```

## 5. Forms, validation, and hidden HTTP methods

Form binding:

```html
<form th:action="@{/addcourse}" th:object="${course}" method="post">
  <input type="text" th:field="*{name}" />
  <span th:if="${#fields.hasErrors('name')}" th:errors="*{name}"></span>
  <button type="submit">Add Course</button>
</form>
```

- `th:action="@{...}"` — form POST URL (Thymeleaf link expression)  
- `th:object` — command object bound to the form  
- `th:field="*{prop}"` — property on that object  
- `#fields.hasErrors` / `th:errors` — show Bean Validation messages  

Controller pattern:

```java
@PostMapping("/addcourse")
public String addCourse(@Valid Course course, BindingResult result, Model model) {
  if (result.hasErrors()) {
    return "add-course"; // redisplay form
  }
  courseService.createCourse(course);
  return "redirect:/index";
}
```

Browsers mainly send GET/POST. For PUT/DELETE, enable:

```properties
spring.mvc.hiddenmethod.filter.enabled=true
```

Then in the template:

```html
<form th:action="@{/delete/{id}(id=${course.id})}" th:method="delete">
  <button type="submit">Delete</button>
</form>
```

Thymeleaf emits a hidden `_method` field; `HiddenHttpMethodFilter` rewrites the verb.

```html
<form action="#" method="post">
  <!-- th:action, th:object, name field + errors -->
</form>
```

## 6. End-to-end Course Tracker (MVC + Thymeleaf)

Typical pieces:

- **`@Controller`** (not `@RestController`) — returns view names  
- Service interface + in-memory or JPA impl  
- Entity with Bean Validation (`@NotEmpty`, `@Min` / `@Max`)  
- Templates: `index.html`, `add-course.html`, `update-course.html`  
- CRUD mappings: GET list/forms, POST create, PUT update, DELETE remove  

Index page often uses `#lists.size(courses)` with `th:switch` for empty vs filled table, `th:href` for edit links, and `th:method="delete"` for deletes.

```java
@GetMapping("/index")
public String index(Model model) {
  model.addAttribute("courses", courseService.findAllCourses());
  return "index";
}
```

```html
<a th:href="@{/update/{id}(id=${course.id})}">Edit</a>
```
