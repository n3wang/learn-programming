缓存层次结构

CPU 每秒可执行数十亿条指令，而主存（DRAM）需要约 200 个 CPU 周期才能响应一次请求。没有缓存，CPU 将有 99% 的时间在等待数据。

解决方案是内存层次结构：一系列速度递减、容量递增、成本递低的存储层级，最快的层级距 CPU 最近。

为什么需要多级缓存？​

存在一个根本性的物理权衡：

  • 更快的存储 → 容量更小、成本更高、功耗更大
  • 更大的容量 → 访问更慢、每 bit 成本更低

核心概念​

缓存命中与缺失​

  • 缓存命中：所请求数据在缓存中找到 → 以缓存速度提供
  • 缓存缺失：未找到 → 从下一级获取（填入缓存行后重试）

平均内存访问时间（AMAT）​

$$AMAT = HitTime + MissRate \times MissPenalty$$

L1 命中时间 = 4 周期，缺失率 = 5%，L2 访问时间 = 12 周期：

AMAT = 4 + 0.05 × 12 = 4.6 周期

若 L2 也缺失而需访问 DRAM（200 周期），代价将急剧增加。

缓存行​

缓存不以单个字节为单位——而是以缓存行（通常 64 字节）为单位存储数据。发生缺失时，整个 64 字节块被取入缓存，利用了空间局部性。

局部性原理​

缓存能发挥作用，是因为程序具有局部性：

类型定义示例
时间局部性最近访问过的数据很快还会被再次访问每次迭代都访问的循环计数器
空间局部性最近访问地址附近的数据也很快会被访问遍历数组

缓存组织方式​

缓存被划分为组（sets），每组包含 N 路（ways）：

  • 直接映射（1 路）：每个地址只能映射到唯一的缓存槽，查找快但容易发生冲突缺失。
  • N 路组相联：每个地址可放入其所在组的任意 N 个槽，命中率更高，但硬件比较电路更复杂。
  • 全相联：任意块可存放在任意位置，用于 TLB；对大型缓存不实用。

替换策略​

缓存已满时，需要驱逐一个块以腾出空间：

  • LRU（最近最少使用）——最常用，最接近最优策略。
  • FIFO（先进先出）——实现更简单。
  • 随机——效果出人意料地接近 LRU，且硬件开销极低（部分 ARM 设计采用）。

对性能的影响​

编写缓存友好的代码
// 差：列主序遍历——几乎每次访问都缺失
for (int j = 0; j < N; j++)
    for (int i = 0; i < N; i++)
        sum += A[i][j];

// 好：行主序遍历——每 8 次访问才缺失 1 次（64B 缓存行 / 8B double）
for (int i = 0; i < N; i++)
    for (int j = 0; j < N; j++)
        sum += A[i][j];

对于 1024×1024 的 double 型矩阵，行主序循环仅凭 L1 命中率提升就能快 5 倍左右。
