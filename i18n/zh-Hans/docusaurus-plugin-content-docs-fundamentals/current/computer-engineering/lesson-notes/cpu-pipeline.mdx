# CPU 流水线阶段

现代 CPU 不会等一条指令完全执行完毕再开始下一条。它们使用**流水线**来重叠执行——就像工厂流水线让多辆汽车同时处于不同工位一样。

## 经典五级 RISC 流水线

大多数计算机体系结构课程教授由 MIPS 和 DLX 推广的五级流水线：

| 阶段 | 缩写 | 操作内容 |
|------|------|---------|
| 取指 | IF | 通过程序计数器（PC）从内存读取下一条指令 |
| 译码 | ID | 解码操作码；读取源寄存器的值 |
| 执行 | EX | ALU 执行运算或计算内存地址 |
| 访存 | MEM | 读取（load）或写入（store）数据内存 |
| 写回 | WB | 将结果写回目标寄存器 |

## 流水线的意义

不使用流水线时，每条指令需要 5 个时钟周期。启用流水线后，一旦流水线填满，每个周期**完成一条指令**：

```
无流水线：I1 需 5 周期，I2 从第 6 周期开始，I3 从第 11 周期开始 ...
有流水线：I1 在第 5 周期完成，I2 在第 6 周期，I3 在第 7 周期 ...
```

吞吐量趋近于每周期 1 条指令（IPC = 1）。真实的乱序执行处理器通过超标量执行（多条流水线）可超过这一上限。

## 流水线冒险

流水线会引入**冒险**——即下一条指令无法在紧接的下一个周期开始执行的情况。

### 结构冒险

两条指令同时需要**同一硬件资源**。

**示例：** 只有单个内存端口的 CPU 无法在同一周期既取新指令（IF 阶段）又读取数据内存（MEM 阶段）。

**解决方案：** 将指令内存（I-cache）与数据内存（D-cache）分离；或让其中一条指令停顿。

---

### 数据冒险（RAW — 先写后读）

某条指令需要读取的寄存器尚未被前一条指令写入。

```asm
ADD R1, R2, R3    # 写入 R1（第 5 周期 WB 阶段才可用）
SUB R4, R1, R5   # 需要读 R1（第 3 周期 ID 阶段就需要）← RAW 冒险！
```

**解决方案 1 — 停顿：** 插入 NOP 气泡等待值就绪，浪费周期。

**解决方案 2 — 转发/旁路：** 将 EX 阶段的输出直接送入下一条指令的 EX 输入端，大多数情况下无需停顿。

---

### 控制冒险（分支冒险）

分支指令改变了 PC，但流水线已经从错误的路径取了后续指令。

```asm
BEQ R1, R0, target    # 分支结果在 EX 阶段末尾才能确定
<推测性取指——可能需要冲刷>
```

**解决方案：** 分支预测（详见[分支预测](./branch-prediction)页面）。

---

:::note 核心要点
流水线是吞吐量优化，而非延迟优化。每条指令仍需 5 个周期；你得到的是稳态下**每周期完成一条**的能力。冒险破坏了这一理想，也正是 CPU 微架构复杂的根本原因。
:::
