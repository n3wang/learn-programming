# 分支预测

当 CPU 遇到**分支**指令（`if`、循环条件、函数调用）时，它尚不知道该走哪条路径——分支条件在若干流水线阶段后才能计算出来。但 CPU 不能暂停：停顿的流水线等于浪费周期。

**分支预测**是硬件在分支结果确定*之前*所做的推测，以便流水线能持续推测性地取指和执行。

## 预测错误的代价

以 15 级流水线、主频 3 GHz 为例：
- **预测正确** → 浪费 0 个周期
- **预测错误** → 冲刷 15 个周期（错误指令被丢弃，流水线重新填充）

以典型负载粗略估算：
```
3 GHz × 30% 分支频率 × 5% 错误率 × 15 周期惩罚
= 每秒浪费约 6.75 亿个周期
```

分支预测准确率提升 1%，对应用性能有显著影响。

## 预测器类型

### 1 位预测器

每个分支存储 1 位：上一次的跳转结果。

- **预测策略：** "这次会与上次一样"
- **问题：** 对于循环 N 次的分支，第一次和最后一次都会预测错误
- **错误率：** 2/N

### 2 位饱和计数器

使用 4 状态有限状态机：

```
强不跳转 ←→ 弱不跳转 ←→ 弱跳转 ←→ 强跳转
```

- 需要**连续两次**预测错误才会改变预测方向
- 能容忍单次异常（如循环的最后一次退出）
- **循环错误率：** 1/N（仅最终退出时预测错误）
- 早期 MIPS R10000 即使用此方案，至今仍是所有现代预测器的基础构件

### 相关预测器（全局历史）

利用**近期多条分支**的结果来预测当前分支，适用于分支之间存在相关性的情况：

```c
if (x > 0) { ... }    // 分支 A
if (y > 0) { ... }    // 分支 B —— 常与分支 A 相关
```

### 锦标赛预测器

结合**局部预测器**（每分支历史表）和**全局预测器**（全部分支历史），通过**选择器**决定对每个分支信任哪一个。Alpha 21264 采用此设计，准确率约 97%。

### TAGE 预测器（当前最先进）

**几何历史长度标记**预测器，使用多张表，每张表以分支 PC 异或不同几何长度的历史（如 5、10、20、40、80 条历史）进行索引，历史最长的匹配项获胜。

- Intel Core（Haswell+）、AMD Zen 3+ 均采用基于 TAGE 的设计
- 在大多数基准测试上准确率 **>99%**

## 分支目标缓冲器（BTB）

即使有完美的方向预测器，在计算出跳转目标地址之前，仍需知道目标地址在哪里。

**BTB** 是一个小型缓存，存储 `(分支 PC → 预测目标地址)` 对，使 CPU 能在预测跳转时立即重定向取指。

没有 BTB，每次间接分支（通过指针的函数调用、虚函数分派）都会导致流水线气泡。

## 安全漏洞：Spectre（2018 年）

:::caution 现实影响
Spectre 漏洞利用了一个事实：**推测执行**的指令（由错误预测触发）即使被回滚，也已经影响了 CPU 的缓存状态。攻击者可以通过时序侧信道读取缓存状态，推断出推测执行期间访问的秘密数据。

这证明了分支预测器的状态对用户空间可观测。现代 CPU 增加了间接分支隔离措施（IBRS、Retpoline、eIBRS），以牺牲部分预测性能换取安全性。
:::

## 总结

| 预测器 | 使用历史 | 典型准确率 | 年代 |
|--------|---------|-----------|------|
| 静态（总是跳转） | 无 | ~65% | 1985 |
| 1 位 | 上次结果 | ~85% | 1990 |
| 2 位饱和计数器 | 1 条分支 | ~90% | 1993 |
| 锦标赛（局部+全局） | 多条 | ~97% | 1998 |
| TAGE | 几何长度 | >99% | 2006+ |
