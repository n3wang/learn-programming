> **Source:** Fluent Python, 2nd Edition — Chapter 5 by Luciano Ramalho

A **data class** is a type that is mostly fields: a record with a decent `__repr__` and `__eq__`, not a 20-line `__init__`. Python gives you three shortcuts:

| Builder | Since | Instances | Class syntax |
|---|---|---|---|
| `collections.namedtuple` | 2.6 | Immutable (`tuple`) | Factory call |
| `typing.NamedTuple` | 3.5 / class body 3.6 | Immutable (`tuple`) | Yes, with annotations |
| `@dataclasses.dataclass` | 3.7 | Mutable by default; `frozen=True` | Decorator, no extra base |

`TypedDict` only annotates mappings; it does not build instantiable classes. Skip it here.

None of these *require* you to inherit a special business base. `namedtuple` / `NamedTuple` produce **tuple subclasses**. `@dataclass` injects methods; your class still subclasses `object` unless you say otherwise.

---

## Why not a hand-written bag of attributes?

A plain class with only `__init__` has a useless `repr` and `==` that compares **identity**, not field values. The builders generate `__init__`, `__repr__`, and `__eq__` (and more, if you ask).

## namedtuple extras

You can index as well as use names. `_fields` lists names. `_make(iterable)` is like `Cls(*row)`. `_asdict()` is a regular `dict` (insertion-ordered). `_replace(**kwargs)` returns a **new** instance. `defaults=` fills the rightmost fields.

Injecting a method by assignment (`Cls.f = fn`) works but is a last resort — prefer a `class` body (`NamedTuple` or `@dataclass`).

## typing.NamedTuple

Same tuple core, plus annotations:

```python
from typing import NamedTuple

class Coordinate(NamedTuple):
    lat: float
    lon: float
    reference: str = "WGS84"
```

`NamedTuple` in the bases list is **not** a real superclass you `issubclass` against; the result **is** a `tuple` subclass. Type hints are **not** checked when the program runs. A checker (Mypy, your IDE) reads them at rest.

A bare `x: int` on a **plain** class only fills `__annotations__`. `NamedTuple` / `@dataclass` turn annotated names into constructor fields. A name **without** an annotation (`c = "spam"`) stays a **class** attribute, not a field.

Prefer `typing.get_type_hints(cls)` over reading `__annotations__` yourself.

## @dataclass

```python
from dataclasses import dataclass, field, asdict, replace

@dataclass
class Player:
    name: str
    score: int = 0
```

Useful decorator flags: `frozen=True` (assign raises `FrozenInstanceError`), `order=True` (sort by fields). `eq` and `frozen` together make instances **hashable**.

**Never** write `guests: list = []`. `@dataclass` rejects `list`/`dict`/`set` literals as defaults. Use:

```python
tags: list = field(default_factory=list)
```

`__post_init__` runs at the end of the generated `__init__` (validation, derived fields). `InitVar` is a constructor-only argument; `ClassVar` keeps a name off the instance fields.

`dataclasses.asdict` / `replace` mirror `_asdict` / `_replace`. `fields(cls)` lists `Field` objects.

A long record (Dublin Core-style) is a typical `@dataclass`: many optional fields, `field(default_factory=list)`, maybe a custom `__repr__`.

## Code smell, then match

A class with only getters for data and **no behavior** can mean the real logic is scattered. That is Fowler’s **data class** smell — not a ban on `namedtuple`. Fine uses: throwaway scripts, **import/export** records you treat as immutable at the boundary, or **scaffolding** you later grow methods onto.

`match` can destructure **any** instance. `case float():` is special for a few builtins. `case float:` (no call) accidentally matches **everything** and binds the name `float`.

Keyword: `case City(continent="Asia", country=cc):`. Positional uses `__match_args__` (the builders fill it): `case City("Asia", _, country):`.

<details>
<summary>🧪 class pattern</summary>

<PistonRunner
  lang="python"
  interactive={false}
  height="320px"
  code={`from typing import NamedTuple

class City(NamedTuple):
    continent: str
    name: str

def label(city):
    match city:
        case City(continent="Asia"):
            return "asia"
        case City():
            return "other"

print(label(City("Asia", "Tokyo")))
print(label(City("Europe", "Paris")))
`}
/>

</details>

## Chapter summary

:::important Key takeaways

1. `namedtuple` / `NamedTuple` / `@dataclass` generate the boring special methods.
2. Tuple builders are immutable; dataclass is mutable unless `frozen=True`.
3. Type hints are not runtime checks.
4. Mutable field defaults need `field(default_factory=...)`.
5. `_asdict` / `asdict` and `_replace` / `replace` clone with edits.
6. Data-only types can be a design smell; class patterns use `__match_args__` or keywords.

:::
