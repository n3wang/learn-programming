> **Source:** Fluent Python, 2nd Edition — Chapter 10 by Luciano Ramalho

A **design pattern** is a known recipe for a recurring design problem. The Gang of Four catalog assumed C++/Smalltalk. In a language with **first-class functions**, several of those recipes shrink: you do not need a class whose only job is one method named `execute` or `discount`.

This chapter is not “use more patterns.” It is: start from Strategy and Command, then replace single-method objects with **callables**.

---

## Strategy, in one paragraph

**Strategy:** a family of algorithms, each interchangeable, so the client can vary the algorithm without rewriting the context.

Ecommerce sketch — an order (the **context**) asks a **promotion** for a discount:

- 5% off the whole order if loyalty points ≥ 1000
- 10% off each line with quantity ≥ 20
- 7% off the whole order if there are ≥ 10 distinct products

The caller chooses one promotion (or a “best of” later). Classic OOP: ABC `Promotion` plus three subclasses with **no instance state**. That is a lot of types for three formulas.

## Functions instead of promo classes

Pass the function in. If `promotion` is an **instance attribute** holding a callable, `self.promotion(self)` is not a method call — you retrieve the function, then pass the order. Bound methods get `self` for free; stored functions do not.

When a strategy **does** keep mutable state, keep a class or a closure. The GoF hint that Strategy objects make good flyweights is a hint you were paying for extra instances — a module-level function is already shared.

## Best of several functions

`best_promo(order)` is `max(fn(order) for fn in promos)`. A list of functions is ordinary data.

| How you fill `promos` | Risk |
|---|---|
| Typed list | Easy to forget a new function |
| `globals()` + `_promo` suffix | Brittle names |
| `inspect` on a module | Every function in that module is assumed to be a promo |
| `@promotion` registration | Explicit; disable one promo by commenting `@promotion` |

## Registration decorator

Same idea as chapter 9: `@promotion` appends the function to a list and returns it. Then `best` cannot forget a promo unless you skip the decorator on purpose.

## Command as a callback

**Command** puts an object between “menu clicked” (invoker) and “document changed” (receiver), with an `execute()` method. Gamma et al. even call commands an OO stand-in for callbacks.

In Python, the invoker can store a **function** and call `command()`. A **macro** is a callable that holds a list of callables:

```python
class Macro:
    def __init__(self, commands):
        self.commands = list(commands)
    def __call__(self):
        for c in self.commands:
            c()
```

Undo and extra state may still want a class with more than `__call__`, or a closure. The smell to watch: an interface with one method named `run` / `do_it` / `execute` — often a function would do.

<CodingExam

## Chapter summary

:::important Key takeaways

1. Strategy plugs an algorithm into a context; in Python that plug is often a function.
2. `self.promo(self)` is a stored callable, not a bound method.
3. `best` is `max` over a list of functions; keep that list honest with a decorator (or accept the maintenance hazard).
4. Command is often a callback; `__call__` plus a list gives macros.
5. First-class functions make some GoF patterns shorter — not every pattern, and not when the strategy is stateful.

:::
