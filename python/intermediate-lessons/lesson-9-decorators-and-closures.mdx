> **Source:** Fluent Python, 2nd Edition — Chapter 9 by Luciano Ramalho

A **decorator** is a callable that takes a function and returns a function (often a **wrapper**). The `@` line is sugar:

```python
@deco
def target():
    ...
# same as: target = deco(target)
```

Decorators run at **import time** — as soon as the `def` finishes — not when you later call the function. Closures (and `nonlocal`) are how wrappers remember the original function and extra state.

This chapter covers:

- What `@` really does, and registration vs wrapping
- Local vs global names (`UnboundLocalError`)
- Closures and free variables
- `nonlocal` when you assign to a captured name
- `functools.wraps`, `@cache` / `@lru_cache`, `@singledispatch`
- Decorator **factories** (decorators that take arguments)

---

## Decorators 101

The decorator may return the **same** function (registration) or a **new** inner function that calls the original.

Three facts: a decorator is a callable; it may replace the decorated name; it runs when the module loads.

## Variable scope

Python decides **at compile time** whether a name in a function is local: if you **assign** to it anywhere in the body, it is local for the whole function. Reading it before that assignment raises `UnboundLocalError`, even if a global with the same name exists.

`global x` means assign/read the module-level `x`. Nested functions that **assign** to a name from the enclosing function need `nonlocal x`.

## Closures

A **closure** is a nested function that keeps **free variables** from the enclosing scope after that scope has returned. Mutating a list (`append`) does not rebind the name. Rebinding a number (`count += 1`) **does** assign, so you need `nonlocal count`.

```python
def make_averager():
    series = []
    def averager(new_value):
        series.append(new_value)
        return sum(series) / len(series)
    return averager
```

## A wrapping decorator

Typical wrapper: accept `*args, **kwargs`, call the original, maybe log, return its result. Copy `__name__` / `__doc__` with `@functools.wraps(func)`.

Stacked `@a` `@b` `def f` means `f = a(b(f))` — the **closest** decorator runs first.

<details>
<summary>🧪 wraps keeps the name</summary>

<PistonRunner
  lang="python"
  interactive={false}
  height="280px"
  code={`import functools

def twice(func):
    @functools.wraps(func)
    def wrapper(x):
        return func(func(x))
    return wrapper

@twice
def inc(n):
    return n + 1

print(inc(3), inc.__name__)
`}
/>

</details>

## Library helpers

| Tool | Role |
|---|---|
| `functools.cache` (3.9+) | Unbounded memoization. Arguments must be hashable. Fine for short scripts. |
| `functools.lru_cache(maxsize=128)` | Same idea with a size cap. Prefer this in long-running services. |
| `functools.singledispatch` | Pick an implementation from the **type of the first argument**. Register more types in other modules. Prefer ABCs over only `int`. |

Naive recursive Fibonacci without a cache repeats work; `@cache` (or `@lru_cache`) keeps one result per `n`. `@cache` can grow without bound — use `lru_cache` when that matters.

```python
from functools import singledispatch

@singledispatch
def show(obj):
    return repr(obj)

@show.register
def _(text: str):
    return text.upper()
```

## Parameterized decorators

`@clock` receives the function. `@clock(fmt)` must be a **factory**: `clock(fmt)` returns the real decorator, which then receives the function.

A class with `__init__(self, fmt)` and `__call__(self, func)` is the same idea and often easier to read for non-trivial wrappers.

If the factory takes optional args, write `@register()` with parentheses when you want the default — otherwise Python would pass the function as that first parameter.

## Challenge: call n times

`times(n)` is a decorator factory. The wrapped function should be called `n` times on the same int, and those return values **summed**.

<CodingExam
  title="call n times"
  heading="Challenge: call n times"
  lang="python"
  filename="main.py"
  prompt="times(n) returns a decorator. Sum n calls of func(x)."
  sampleLog={`(input) 3 5

  starter={`def times(n):
    def decorate(func):
        def wrapper(x):
            return func(x)
        return wrapper
    return decorate
`}
  wrapSuffix={`

    return v

print(ident(x))
`}
  tests={[
    { name: '3 times 5', stdin: '3 5', equals: '15' },
    { name: '1 times 9', stdin: '1 9', equals: '9' },
    { name: '4 times 2', stdin: '4 2', equals: '8' },
  ]}
/>

## Chapter summary

:::important Key takeaways

1. `@deco` means `f = deco(f)` and runs at import time.
2. Registration keeps the same function; most decorators return a wrapper.
3. Assignment anywhere in a function makes that name local.
4. Closures keep enclosing bindings; `nonlocal` is required to rebind them.
5. Use `wraps`, `cache` / `lru_cache`, and `singledispatch` from `functools`.
6. Parameterized `@deco(x)` is a factory that returns the real decorator.

:::
