> **Source:** Fluent Python, 2nd Edition — Chapter 3 by Luciano Ramalho

Python programs are full of **dicts**, even when you never write `{...}`. Class attributes, instance `__dict__`, module namespaces, and keyword arguments are mappings. Built-ins live in `__builtins__.__dict__`. That is why `dict` is heavily optimized, and why **hash tables** show up again for `set` and `frozenset`.

Sets give you the usual math: union, intersection, difference, subset tests. Used well, they replace nested loops and `if` chains.

This chapter is about **using** mappings and sets. We will cover:

- Dict comprehensions, `**` unpacking, and `|` / `|=` merges (3.9+)
- Mapping patterns in `match` (3.10+)
- `get`, `setdefault`, `defaultdict`, and `__missing__`
- Nearby types: `OrderedDict`, `ChainMap`, `Counter`, views, read-only proxies
- Sets, set comprehensions, and set ops on `dict.keys()` / `dict.items()`

---

## Why dicts matter

Keys must be **hashable**: a stable `__hash__`, and `__eq__` that agrees with the hash. `str`, numbers, and `frozenset` are hashable. A `tuple` is hashable only if **every** item is. A `list` is never a valid dict key.

Lookups by key are fast even for huge dicts. Since Python 3.7, insertion **order** of keys is part of the language. Dicts still cost extra memory compared to a plain array of pointers. Adding instance attributes *after* `__init__` can make an object’s `__dict__` less compact.

`d.get(k, default)` is for “missing is OK.” `d[k]` is fail-fast (`KeyError`).

## Dict comprehensions

A **dictcomp** builds a mapping from `key: value` pairs:

```python
pairs = [(1, "a"), (2, "b")]
swapped = {word: n for n, word in pairs}
# {'a': 1, 'b': 2}
```

You can filter and transform in the same expression, same idea as listcomps.

## Unpacking and merging

`**` splats a mapping into a dict literal or into keyword arguments. Later keys **win** in a literal:

```python
{"a": 0, **{"x": 1}, "y": 2, **{"x": 4}}
# {'a': 0, 'x': 4, 'y': 2}
```

Python 3.9+ also has **union** on mappings, same symbols as sets:

```python
d1 | d2      # new dict; keys from d2 overwrite d1
d1 |= d2     # update d1 in place
```

The left operand’s type is usually the result type for `|`.

## Mapping patterns

`match` can destructure **mappings**. Extra keys on the subject are OK (partial match). Key order in the pattern does not matter.

```python
match record:
    case {"kind": "book", "who": name}:
        ...
    case {"kind": "film", "who": name}:
        ...
    case {"kind": "book"}:
        ...  # incomplete book
    case _:
        ...
```

Capture leftovers with `**details` as the last entry in the pattern. Matching uses `get`-style lookup: it does **not** create missing keys (unlike some `defaultdict` tricks).

## Missing keys: get, setdefault, defaultdict

Updating a **mutable** value in a dict is a common trap:

```python
# two lookups (or three if missing)
xs = d.get(k, [])
xs.append(v)
d[k] = xs
```

`setdefault` does “get or insert” in **one** hash lookup:

```python
d.setdefault(k, []).append(v)
```

`collections.defaultdict(list)` makes `d[k].append(v)` work even when `k` is new. The factory runs only for **`d[k]`** (`__getitem__`), not for `.get` or `in`.

If you subclass `dict`, `__missing__` is called from `__getitem__` only. Prefer `collections.UserDict` when you grow a custom mapping: it stores items in `.data` and avoids `dict` shortcuts that force extra overrides.

## Other mapping types

| Type | Role |
|---|---|
| `OrderedDict` | Equality **includes order**; `move_to_end`; better when you reorder often (LRU-style). Plain `dict` already keeps insertion order. |
| `ChainMap` | Search several mappings as one. Writes go to the **first** map. |
| `Counter` | Integer counts; `+` / `-`; `most_common(n)`. |
| `types.MappingProxyType` | Read-only **view** of a live dict (updates to the original show through). |
| `shelve` | Disk-backed mapping of string keys to picklable values (know the pickle caveats). |

`d.keys()`, `.values()`, `.items()` return **views**: cheap, live, not a copied list. `values` is not a set. `keys` always behaves like a set of hashable keys. `items` is a set only if **values** are hashable too.

```python
d1.keys() & d2.keys()   # set of shared keys
```

## Sets

A **set** holds unique hashable objects. `frozenset` is the immutable (and hashable) sibling, so it can live inside another set or be a dict key.

```python
{"spam", "eggs"} | {"eggs", "bacon"}   # union
needles & haystack                     # intersection
```

Empty set is `set()`, never `{}`. `{1, 2, 3}` is faster than `set([1, 2, 3])`.

**Setcomps:** `{x for x in items if ...}`

Operators like `&` want set operands. Methods such as `.union(it)` accept any iterable of hashable items. Star-unpack: `{*a, *b, *c}`.

Hash tables mean: membership is fast; sets use extra memory; **do not** rely on element order; growing a set can reshuffle existing items.

To drop duplicates but keep **first** seen order, `list(dict.fromkeys(items))` is the usual trick (dict keys are unique and ordered).

## Chapter summary

:::important Key takeaways

1. Dicts are everywhere in the language. Keys must be hashable; order is insertion order.
2. Dictcomps, `**`, and `|` / `|=` are the modern ways to build and merge mappings.
3. Mapping `match` is a partial match on keys; it will not auto-insert missing keys.
4. Prefer `setdefault` or `defaultdict` when you grow lists (or other mutables) per key. `__missing__` only hooks `d[k]`.
5. Views are live; `keys()` (and `items()` when values are hashable) speak set operators.
6. Sets enforce uniqueness and express algebra (`| & - ^`). Empty set is `set()`.

:::
