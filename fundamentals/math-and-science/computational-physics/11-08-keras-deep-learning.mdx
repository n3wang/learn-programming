# 11.8 Keras: Python’s deep-learning API

> **Source:** Ideas from *Computational Physics* (Landau, Páez, Bordeianu), §11.7. Rewritten in original wording — **no** textbook `Keras.py` dump. Continues [11.7b](./11-07b-ml-clustering-labs). Next: [11.8b](./11-08b-keras-labs).

**Keras** (via `tf.keras`) is a high-level API for stacking and training deep nets. **Deep** = data flows through **multiple layers**. A **layer** takes inputs, applies weights / biases / activations, and emits outputs to the next layer. A **dense** (fully connected) layer links every unit to every unit in the previous layer.

## `Dense` knobs (conceptually)

Typical arguments (names matter more than memorizing defaults):

| Argument | Role |
| --- | --- |
| `units` | Output dimension |
| `activation` | `sigmoid`, `relu`, `tanh`, `selu`, … |
| `use_bias` | Add bias terms |
| `kernel_initializer` | How weights start (e.g. Glorot) |
| `*_regularizer` / `*_constraint` | Penalties / bounds on weights |

## Hubble again, one dense unit

A minimal regression model is a **single** `Dense(units=1, input_shape=[1])` inside a `Sequential` model: that is exactly $y=wr+b$. Compile with MSE loss and an optimizer (e.g. Adam), `fit` for many epochs, watch Loss fall, then read `get_weights()` for slope and intercept.

![Figure 11.11 — Loss vs epoch; learned line.](/img/computational-physics/fig-11-11-keras-hubble.svg)


## Takeaway

1. Keras layers = reusable building blocks.
2. Dense = affine map + optional nonlinearity.
3. `compile` + `fit` = Loss + optimizer + epochs.
4. One-unit Dense ≡ linear regression (Hubble toy).
