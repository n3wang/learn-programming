## Perceptron & multilayer nets

A **perceptron** (neuron) takes inputs, applies **weights**, forms a **linear combination** $z = w^\top x + b$, then passes $z$ through an **activation** $\sigma$. Stack neurons into layers → **multilayer perceptron (MLP)** / feed-forward net.

- **Input layer** — features  
- **Hidden layers** — intermediate transforms (“deep” = many of these)  
- **Output layer** — prediction (regression number, class logits / probabilities)

Inputs combine linearly; **nonlinear** activations make the overall map nonlinear — that is why NNs shine on complex patterns that linear models miss. Pure stacks of linear layers without nonlinearities collapse to one linear map.

## Activation functions

Common activations (know formulas + when they show up):

| Name | Formula (sketch) | Notes |
| --- | --- | --- |
| Unit / sign | step or $\mathrm{sign}(z)$ | Classic perceptron variants |
| Linear | $\sigma(z)=z$ | Like linear / Adaline |
| Sigmoid | $\sigma(z)=1/(1+e^{-z})$ | $(0,1)$; saturates |
| tanh | $\tanh(z)$ | $(-1,1)$; saturates |
| ReLU | $\max(0,z)$ | Default hidden unit; sparse, helps vanishing grads |
| softplus | $\ln(1+e^{z})$ | Smooth ReLU-like |

Interview depth: trade-offs (saturation → vanishing gradients; ReLU can “die” for $z<0$).

## Forward pass & backpropagation

**Feed-forward:** data flows input → hidden → output. Training compares prediction to target with a **loss** — often **MSE** for regression, **cross-entropy** for classification — then **backpropagation** sends error signals backward.

Chain rule (scalar sketch): if $z$ is the network output and $L(z,y)$ the loss,

$$
\frac{\partial L}{\partial w}=\frac{\partial L}{\partial z}\frac{\partial z}{\partial w},
\qquad
w \leftarrow w - \alpha\frac{\partial L}{\partial w}.
$$

$\alpha$ is the **learning rate**. Updates use SGD / mini-batches. ML-heavy interviews may whiteboard this for tiny models (linear / logistic).

Hyperparameters that come up constantly: learning rate, # hidden layers / width, activations, batch size, epochs, regularization.

| $\alpha$ too small | Training crawls / stalls |
| --- | --- |
| $\alpha$ too large | Unstable / overshoots, may “converge” poorly |

## Training problems & optimizers

Deep nets train millions of weights and many hyperparameters — things go wrong.

**Vanishing gradients:** chain-rule products of small derivatives (classic sigmoid / tanh tails) → early layers barely update. **Exploding gradients:** products blow up. Mitigations: ReLU-family activations, residual / skip connections (ResNets), gated memory (LSTMs), gradient clipping, careful init.

**Vanilla SGD issues:** noisy steps, bad $\alpha$, saddle points / poor local minima, features with different scales/frequencies.

**Momentum:** keep a **velocity** that exponentially averages past gradients so updates keep a consistent direction/speed:

$$
v \leftarrow \beta v + g, \qquad w \leftarrow w - \alpha v.
$$

(Modern practice also uses Adam-family adaptive methods — know the *problem* they address even if you skip every formula.)

## Transfer learning

**Transfer learning** reuses weights from a model trained on a large related dataset (ImageNet, BERT corpora), then adapts / fine-tunes on your smaller task. Ideal when you lack data but a strong pretrained pool exists — e.g. hot-dog detector: start from ImageNet features, then fine-tune on your 100 hot-dog photos.

## Addressing overfitting

Deep nets overfit easily (huge capacity). Interview toolkit:

| Technique | Idea |
| --- | --- |
| More data | Best variance fix if you can collect / augment |
| Input standardization | 0 mean / unit variance → stabler, faster learning (avoids wild weight scales) |
| **Batch normalization** | Normalize activations within a mini-batch so hidden reps stay well-scaled; layers train more independently; also regularizes |
| **Dropout** | Randomly deactivate neurons each step → train an ensemble of thinner nets; noise ≈ regularizer |

Batch norm + dropout both inject a kind of training noise that curbs co-adaptation.

## Architectures: CNN, RNN, LSTM

| Family | Core idea | Typical use |
| --- | --- | --- |
| **CNN** | Convolution filters on local neighborhoods + pooling + dense head | Vision — edges/textures → objects; translation-ish invariance from pooling |
| **RNN** | Directed recurrence + **hidden state (memory)** along a sequence | Audio / video / text where context depends on history; variable lengths |
| **LSTM** | Cell + **input / output / forget gates** regulating memory flow | Long-range dependencies — preferred over vanilla RNNs in practice |

CNN pipeline sketch: conv (+ ReLU) → pool → … → flatten → fully connected → softmax.

RNNs are **not** plain feed-forward: they reuse state across time. LSTMs add gates so useful signal can persist longer than a vanilla RNN’s short memory.
