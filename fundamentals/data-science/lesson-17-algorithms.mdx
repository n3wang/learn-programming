## Recursion vs iteration

A recursive function needs a **base case** and a **recursive case**. Naïve Fibonacci recomputes the same `fib(k)` exponentially often and can blow the call stack. Iterative Fibonacci (or memoized recursion) is $O(N)$ time.

## Greedy algorithms

Pick the locally best option each step. Works for canonical coin systems; **fails** on 0/1 knapsack. Say the greedy-choice property out loud — or switch to DP.

## Dynamic programming & knapsack

Needs **optimal substructure** + **overlapping subproblems**. Top-down memo or bottom-up table.

For 0/1 knapsack with capacity $W$ and item weight $w_i$, value $v_i$:

$$f[j] = \max(f[j], f[j-w_i]+v_i)$$

Loop $j$ **downward** so each item is used at most once. Loop upward for unbounded/complete knapsack.

### Written: knapsack tradeoffs

<ProblemSet id="ds-algo-knapsack-write">
  <Problem
    type="concept"
    title="0/1 vs unbounded"
    minWords={45}
    keywords={['downward', 'reuse']}
    prompt={`Explain how the 1-D DP loop direction encodes 0/1 vs unbounded knapsack, and give a tiny numeric counterexample where ratio-greedy fails for 0/1.`}
    answer={`In the rolling array, processing capacities from W down to w ensures f[j−w] still reflects the previous item only, so each item is taken at most once (0/1). Scanning upward lets an update to f[j−w] feed f[j] again in the same item pass — unbounded reuse. Counterexample: items (weight,value)=(5,6),(4,5),(3,4) wait — classic: (2,3),(3,4),(4,5) with W=5. Best density is 3/2=1.5 then leftover 3 cannot take (3,4); taking (2,3)+(3,4)=7 beats (4,5)=5.`}
  />

    type="concept"
    title="Complexity knobs"
    minWords={40}
    keywords={['O(nW)', 'pseudo']}
    prompt={`Why is O(nW) knapsack called only weakly polynomial / pseudo-polynomial, and when would you refuse that DP?`}
    answer={`W is numeric magnitude, not bit-length: if W=10^12 the table is impossible even for small n. The runtime is polynomial in n and W, not in the input size Θ(n log W). Refuse plain DP when W is huge; switch to meet-in-the-middle (n≈40), approximations, or exploit structure (unary weights, few distinct weights).`}

### Labs: knapsack variants

<ExerciseSet>
  <CodeExercise
    title="0/1 knapsack value"
    heading="algo-knap-01"
    lang="python"
    filename="main.py"
    prompt="0/1 knapsack: line1 n W; line2 n values; line3 n weights. Print max value (float ok)."
    starter={`def knapsack(values, weights, W):
    return 0.0
`}
    wrapSuffix={`
n, W = map(int, input().split())
values = list(map(float, input().split()))
weights = list(map(int, input().split()))
print(knapsack(values, weights, W))
`}
    solution={`def knapsack(values, weights, W):
    dp = [0.0] * (W + 1)
    for value, weight in zip(values, weights):
        for w in range(W, weight - 1, -1):
            cand = dp[w - weight] + value
            if cand > dp[w]:
                dp[w] = cand
    return dp[W]
`}

    solution={`def unbounded(values, weights, W):
    dp = [0] * (W + 1)
    for w in range(1, W + 1):

            if weight <= w:
                dp[w] = max(dp[w], dp[w - weight] + value)
    return dp[W]
`}
