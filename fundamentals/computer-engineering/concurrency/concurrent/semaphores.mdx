# Semaphores

Dijkstra introduced the **semaphore** as one primitive for synchronization [D68b,D72] — usable as both a **lock** and a **condition-like** ordering tool.

**Crux:** how to use semaphores? Binary vs general? Build them from locks/CVs (and the reverse)?

## Definition

POSIX: `sem_init`, `sem_wait` (historically **P** / down), `sem_post` (**V** / up).

```text
wait:  value--;  if value < 0 → sleep
post:  value++;  if waiters → wake one
```

Assume these steps are atomic (implemented with locks underneath). When negative, Dijkstra’s view: magnitude ≈ number waiting (Linux “Zemaphores” often never go below 0).

## Binary semaphore = lock

Init to **1**. `wait` before CS, `post` after. Second waiter drives value to **−1** and sleeps until the holder posts.

## Ordering (join)

Init to **0**. Parent `wait`, child `post`. Works whether parent waits first (sleeps at −1) or child posts first (parent sees 1 and returns).

## Producer / consumer

Semaphores **empty=MAX**, **full=0**. Producer: `wait(empty); put; post(full)`. Consumer: `wait(full); get; post(empty)`.

**Race:** concurrent `put`/`get` on indices need a **mutex**.

**Deadlock:** `wait(mutex)` then `wait(full)` while holding mutex — producer cannot enter to `post(full)`.

**Fix:** wait on empty/full **outside**; hold mutex **only** around put/get (Fig 31.12).

## Reader-writer locks

Allow many concurrent readers **or** one writer [CHP71]. First reader takes `writelock`; last reader releases it. Writers only take `writelock`.

Useful pattern — but can **starve writers**, and fancy R/W often loses to a **simple lock** (Hill’s Law: simple/dumb can be fastest).

## Dining philosophers

Five philosophers, five forks (semaphores=1). Need left+right to eat.

**Broken:** everyone `wait(left)` then `wait(right)` → circular wait / deadlock.

**Fix:** break the cycle (e.g. philosopher 4 acquires **right then left**) [D71].

## Implementing semaphores

**Zemaphore:** mutex + CV + `value`; wait while `value<=0`; post increments and signals (Fig 31.16). Building **CVs out of semaphores** is surprisingly hard [B04].

:::tip Be careful with generalization
Semaphores generalize locks+CVs — but Lampson: “Don’t generalize; generalizations are generally wrong” [L83].
:::

## Summary

| Use | Init | Pattern |
|---|---|---|
| **Lock** | 1 | wait / CS / post |
| **Join / signal event** | 0 | waiter wait; signaler post |
| **Bounded buffer** | empty=MAX, full=0, mutex=1 | resource waits outside mutex |
| **R/W** | writelock=1 | first/last reader gate writers |
| **Philosophers** | forks=1 | break circular acquire order |
