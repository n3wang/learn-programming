# Beyond Physical Memory: Mechanisms

So far every address space fit in RAM. Real systems support **many large** address spaces at once. That needs another level in the memory hierarchy: a big, slower device (disk or SSD) to hold pages that are not in demand.

**Crux:** how use a larger, slower device to **transparently** give the illusion of a huge virtual address space?

Convenience: allocate without worrying whether RAM is full. Multiprogramming also needs this — early machines could not hold every process’s pages at once.

## Swap space

Reserve disk for moving pages: **swap space**. The OS reads/writes it in page-sized units and remembers each page’s **disk address**. Capacity of swap bounds how much “memory” the system can pretend to have.

Fig 21.1 toy: 4 physical frames, 8 swap blocks. Several processes share RAM; some valid pages live only on disk; one process may be fully swapped out.

Code pages can also be re-fetched from the **file system binary** (not only swap) if the OS evicts them.

## The present bit

On a reference: TLB first. On miss, walk the PTE.

Add a **present bit**:

- **1** — page in physical memory; PFN usable  
- **0** — not in memory (on disk); access is a **page fault**

“Fault” is a bit of a misnomer for a *legal* but not-present page — historically the same trap path as illegal accesses.

## The page-fault handler

Almost always **software** (even with a hardware-managed TLB). Reasons: disk I/O is slow (OS overhead is noise), and hardware would need to understand swap and I/O.

Rough flow when present=0:

1. Read **disk address** from the PTE (bits that otherwise hold the PFN)  
2. Find a free frame (or **evict** — next chapter’s policy)  
3. **DiskRead** into that frame (process **blocked**; other jobs run)  
4. Set present=1, store PFN, **retry** the instruction (may TLB-miss then hit)

## Control flow (hardware sketch)

On TLB miss, three important cases:

| Case | Meaning |
|---|---|
| Valid + present | Fill TLB, retry |
| Valid + not present | **PAGE_FAULT** → OS handler |
| Invalid | **SEGMENTATION_FAULT** (bug) → usually kill |

## When memory is full

Evicting to free a frame is the **page-replacement policy** (next lesson). Wrong victims → disk-speed execution.

## Watermarks and the page daemon

Do not wait until free=0. Keep a cushion with **low watermark (LW)** and **high watermark (HW)**:

- Free &lt; LW → wake **page daemon** / swap daemon  
- Evict until free ≥ HW → sleep  

Batching enables **clustering** writes to swap (better disk efficiency) [LL82].

:::tip Do work in the background
Background reclaim (and buffered writes) groups I/O, improves latency, and uses idle time [G+95].
:::

## Summary

| Piece | Role |
|---|---|
| **Swap space** | Disk backing for pages |
| **Present bit** | In RAM vs on disk |
| **Page fault** | OS brings page in (maybe after eviction) |
| **LW / HW + daemon** | Proactive reclaim + clustered I/O |

Transparency: the process still sees a private contiguous VA; behind the scenes pages move between RAM and disk.
