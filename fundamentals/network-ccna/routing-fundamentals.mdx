> **Track:** Network CCNA — eighth chapter. Packets stay on one LAN until a **router** forwards them. This chapter is **how a host chooses a dest MAC**, how a router **fills** and **reads** `show ip route`, and how you **type a static**. Exam 3.1 (read the table), 3.2 (default forwarding), 3.3 (IPv4 statics). IPv6 statics wait for a later chapter.

# Routing Fundamentals

**Routing** is two jobs that share a name. First: the router **builds a routing table** — known prefixes and what to do with them. Second: it **forwards packets** using that table. Switches fill a MAC table by watching frames. A router’s table starts **empty**. Connected and local rows appear when you address an interface and bring it **up/up**. Everything else is **static** (you type it) or **dynamic** (a protocol such as OSPF, later).

A packet is never sent on the wire by itself. It always rides in a **frame**. Layer 3 names the **end host**. Layer 2 names the **next box**.

## Same LAN versus a remote dest

PC1 is `192.168.1.11/24`. That prefix is `192.168.1.0`–`192.168.1.255`.

If the dest IP is **inside** that range (PC2 at `.12`), PC1 frames **directly to PC2’s MAC**. No router is in the path. If PC1 does not yet have that MAC, it **ARPs** `192.168.1.12`.

<LessonFigure src="/img/ccna/fig-9-1.png" alt="Same LAN: PC1 frames the packet straight to PC2’s MAC; the router isn’t involved." caption="Figure 9.1 — Same LAN: PC1 frames the packet straight to PC2’s MAC; the router isn’t involved." maxWidth={480} />

If the dest IP is **outside** that range (PC3 at `192.168.3.11`), PC1 still writes **PC3** in the IPv4 dest. The Ethernet dest is the **default gateway** — here R1 `192.168.1.1` on G0/1. PC1 ARPs **the gateway IP**, not the remote host. Broadcast ARP never leaves the LAN, so a campus-wide ARP for PC3 would not work.

<LessonFigure src="/img/ccna/fig-9-2.png" alt="Different LAN: PC1 frames the packet to its default gateway, R1, which forwards it on." caption="Figure 9.2 — Different LAN: PC1 frames the packet to its default gateway, R1, which forwards it on." maxWidth={600} />

The gateway IP is often the **first usable** address of the LAN (`.1`). That is custom, not a protocol rule. Hosts usually learn it from **DHCP** (later). On Windows, `ipconfig` prints IPv4 address, subnet mask, and default gateway. The gateway is stored as an **IP**. The MAC still comes from ARP.

A **cloud** on a drawing is “stuff we are not unpacking.” It might be the internet. It might be the rest of the campus.

## What the gateway actually does

R1 receives a frame whose dest MAC is **its own**. Not its MAC? Discard the frame — routers do not flood.

<LessonFigure src="/img/ccna/fig-9-3.png" alt="Inside R1: receive the frame, look up the destination IP, re-frame it out G0/1." caption="Figure 9.3 — Inside R1: receive the frame, look up the destination IP, re-frame it out G0/1." maxWidth={560} />

Inside, dest IP is either:

- **This router** (a local `/32`) — keep de-encapsulating. The packet is for R1.
- **Someone else** — look up the dest IP in the routing table.
  - A matching **non-local** route → encapsulate in a **new** frame and send it out the interface the route names (directly to the dest host if the net is connected, otherwise to the **next hop**).
  - **No match** → **drop**. Routers never flood packets. Switches sometimes flood unknown unicasts. Different layer, different rule.

`show ip route` is the table. With no addresses yet you get the legend of codes and **Gateway of last resort is not set** — no default route.

Address G0/0 `192.168.1.1 255.255.255.0` and G0/1 `192.168.2.1 255.255.255.0`, `no shutdown`, and four rows appear:

```text
     192.168.1.0/24 is variably subnetted, 2 subnets, 2 masks
C       192.168.1.0/24 is directly connected, GigabitEthernet0/0
L       192.168.1.1/32 is directly connected, GigabitEthernet0/0
```

**Variably subnetted** is a heading, not a route. It means “two prefixes that sit inside that classful block, two different masks.”

- **C (connected)** — the **network** on that interface. Prefix length matches the configured mask (`/24` here). Forward **directly to the dest host** (ARP that host).
- **L (local)** — the interface’s **own** IP with **/32**. Receive for self. Without L, a lone C would try to hairpin packets for `192.168.1.1` out G0/0.

Filter: `show ip route | include C` or `| include L`.

Exam 3.3 language:

- **Network route** — more than one dest IP, prefix **shorter than /32**. Connected routes are network routes.
- **Host route** — exactly one dest IP, **/32**. Local routes are host routes.

A `/24` route covers 256 addresses (last octet free). A `/32` covers one. That is why L beats C for the router’s own address.

<LessonFigure src="/img/ccna/fig-9-5.png" alt="A /32 local route: every bit is fixed, so it matches exactly one address." caption="Figure 9.5 — A /32 local route: every bit is fixed, so it matches exactly one address." maxWidth={560} />

<LessonFigure src="/img/ccna/fig-9-4.png" alt="A /24 route: the first three octets are fixed, the last octet can be anything." caption="Figure 9.4 — A /24 route: the first three octets are fixed, the last octet can be anything." maxWidth={560} />

## Most specific matching route

**Matching** = the dest IP sits inside the route’s prefix. **Most specific** = **longest prefix length**.

Dest `192.168.1.1` matches both `192.168.1.0/24` and `192.168.1.1/32`. R1 picks **/32** and **receives**. Dest `192.168.1.12` matches only the `/24`, so R1 ARPs PC2 and forwards.

<LessonFigure src="/img/ccna/fig-9-6.png" alt="Two routes match and R1 picks the most specific: the /32 local route beats the /24." caption="Figure 9.6 — Two routes match and R1 picks the most specific: the /32 local route beats the /24." maxWidth={560} />

`/32` is the longest useful IPv4 prefix. `/0` is the shortest — every IPv4 address. A `/32` always wins if it matches.

Layer 2 vs Layer 3:

- Switch: dest MAC in the table → **exact** match, or flood.
- Router: dest IP in the table → **longest prefix**, or drop (or use a default).

| Match | Action |
| --- | --- |
| One or more non-local routes | Forward on the longest match |
| A local `/32` | Receive for self |
| Nothing | Drop |

## Static routes for remote prefixes

Connected and local cover **this** box’s interfaces. They do **not** cover a LAN three hops away. Two ways to learn those:

- **Dynamic** — OSPF and friends, later chapters.
- **Static** — you type `ip route`.

To send toward a remote dest, the router builds a frame to the **next hop** (the next router), not to the dest host. Dest **IP** stays the original host.

<LessonFigure src="/img/ccna/fig-9-7.png" alt="PC1 → PC3 across R1, R2, and R3: a routing lookup and a new frame at every router." caption="Figure 9.7 — PC1 → PC3 across R1, R2, and R3: a routing lookup and a new frame at every router." maxWidth={600} />

You do **not** have to teach every transit prefix. For PC1 ↔ PC3, each router needs a path to **192.168.1.0/24** and **192.168.3.0/24**. R1 already has `.1.0/24` connected. R3 already has `.3.0/24`. Minimum statics:

| Router | Prefix | Next hop |
| --- | --- | --- |
| R1 | 192.168.3.0/24 | 192.168.12.2 (R2) |
| R2 | 192.168.1.0/24 | 192.168.12.1 (R1) |
| R2 | 192.168.3.0/24 | 192.168.23.2 (R3) |
| R3 | 192.168.1.0/24 | 192.168.23.1 (R2) |

R1 does not need `192.168.23.0/24`. It only needs “toward `.3.0/24`, give it to R2.”

<LessonFigure src="/img/ccna/fig-9-8.png" alt="R1 doesn’t know the path past R2; its static route just hands the packet to R2." caption="Figure 9.8 — R1 doesn’t know the path past R2; its static route just hands the packet to R2." maxWidth={560} />

Three shapes, all from global config:

```text
ip route dest-network netmask next-hop
ip route dest-network netmask exit-interface
ip route dest-network netmask exit-interface next-hop
```

<LessonFigure src="/img/ccna/fig-9-9.png" alt="The static routes R1, R2, and R3 need so PC1 and PC3 can reach each other both ways." caption="Figure 9.9 — The static routes R1, R2, and R3 need so PC1 and PC3 can reach each other both ways." maxWidth={600} />

### Recursive — next-hop IP only

```text
R1(config)# ip route 192.168.3.0 255.255.255.0 192.168.12.2
```

`show ip route` prints `S 192.168.3.0/24 [1/0] via 192.168.12.2`. Code **S**. `[1/0]` is administrative distance and metric — chapter 17. Two lookups: the static names the next-hop **IP**; a second lookup (the connected `/24`) names **G0/0**. Then ARP for that next hop. One ARP entry serves the whole remote prefix.

### Directly connected static — exit interface only

```text
R1(config)# ip route 192.168.3.0 255.255.255.0 g0/0
```

The table lies a little: `S 192.168.3.0/24 is directly connected, GigabitEthernet0/0`. R1 tries to ARP **PC3** on G0/0. That broadcast dies on R2’s LAN. It works only if R2 **proxy ARPs** — replies with **R2’s** MAC because R2 **has a route** to `.3.0/24`. Cisco routers proxy-ARP by default; other vendors may not. Even when it works, R1 stores **one ARP per remote host**. Prefer recursive or fully specified in a real net. Know the term for the exam.

<LessonFigure src="/img/ccna/fig-9-10.png" alt="Proxy ARP: R2 answers R1’s ARP for PC3’s address because it has a route there." caption="Figure 9.10 — Proxy ARP: R2 answers R1’s ARP for PC3’s address because it has a route there." maxWidth={560} />

### Fully specified — both

```text
R1(config)# ip route 192.168.3.0 255.255.255.0 g0/0 192.168.12.2
```

Table: `S 192.168.3.0/24 [1/0] via 192.168.12.2, GigabitEthernet0/0`. Exit interface and next hop are already known. No second lookup, no proxy ARP. Recursive vs fully specified is a wash on a LAN Ethernet. Directly connected statics are the ones to avoid.

## Default route — `0.0.0.0/0`

A **default route** matches **every** IPv4 address. It is the **least** specific prefix, so it is used only when **nothing longer** matches. Typical use: one hop toward the **internet**. Nobody’s access router holds the global table.

```text
R1(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.2
```

<LessonFigure src="/img/ccna/fig-9-11.png" alt="Two specific routes plus a default route (0.0.0.0/0) toward the internet." caption="Figure 9.11 — Two specific routes plus a default route (0.0.0.0/0) toward the internet." maxWidth={560} />

After that, `Gateway of last resort is 203.0.113.2 to network 0.0.0.0` and `S* 0.0.0.0/0 [1/0] via 203.0.113.2`. The star marks a **candidate default**. Gateway of last resort is the router’s name for a default gateway.

With a default installed, “no match” stops happening: leftovers go to the ISP. More-specific statics (campus LANs) still win because they are longer than `/0`.

`show ip route static` prints only S rows.

## Lab notes the exam likes

`ip route 10.0.0.0 255.0.0.0 192.0.2.1` is a **network** route (`/8`, not `/32`) and a **recursive** route (next-hop IP only).

Drag-and-drop the three static *forms*: exit interface only → **directly connected**; next-hop IP only → **recursive**; both → **fully specified**. A `0.0.0.0/0` next-hop-only line is still recursive; it is also a default.

In a sim, draw the dest LANs first, then type the four (or six) `ip route` lines. The question will say if it wants recursive, fully specified, or exit-interface.
