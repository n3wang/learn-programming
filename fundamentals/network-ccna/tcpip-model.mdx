# The TCP/IP Networking Model

Ethernet told us how two neighbors share a wire. A PC retrieving a page from a server on another continent needs more than that. Several **protocols** have to cooperate, each doing one job.

A **protocol** is a shared set of rules for how to talk. Two hosts using different protocol sets are two people speaking different languages.

This chapter is a **framework**, not the last word on any one protocol. Later chapters fill in Ethernet switching, IP addressing, TCP and UDP. You need the map first so those pieces have a shelf.

The exam list does not name “OSI” or “TCP/IP model.” People who work on networks still talk in these layers every day.

## Why models are layered

Early networks were often **vendor-owned**. IBM spoke IBM. Mixing brands was a project.

The useful alternative is **vendor-neutral**: one model, protocols anyone may implement. A Mac can read a site on Linux. A Windows PC can send mail that an Android phone opens.

A **networking model** splits “get this data from here to there” into **layers**. Each layer is a job description. Several protocols can apply for that job. The mail app does not care whether the last hop was **Ethernet on UTP** or **Wi-Fi on radio**, as long as the layer under it delivered a frame.

Two models matter in conversation:

- **OSI** — how we still *name* layers, even though it is not what the internet runs.
- **TCP/IP** — what modern networks actually run. The name comes from two of its protocols: **TCP** and **IP**.

## The OSI model (names you will hear)

The **Open Systems Interconnection** model is an ISO framework with **seven** layers. ISO’s short name is not “IOS”; the organization treats **ISO** as a word from Greek *isos* (“equal”), so it stays the same in every language.

| Layer | Name |
| --- | --- |
| 7 | Application |
| 6 | Presentation |
| 5 | Session |
| 4 | Transport |
| 3 | Network |
| 2 | Data Link |
| 1 | Physical |

You do not need a deep OSI history for this track. You **do** need the seven names, because people still say “Layer 3” and “Layer 7” when they mean TCP/IP jobs.

A common memory hook, bottom to top: **Please Do Not Throw Sausage Pizza Away.**

## The TCP/IP model

TCP/IP grew out of US DoD / DARPA research (once called the ARPANET model) and is written down as the **Internet Protocol Suite**. The documents are **RFCs** from the **IETF**. Some RFCs are jokes. The ones that became **Internet Standards** are the protocols the internet actually speaks: IP, TCP, HTTPS, and the rest.

RFC 1122 describes **four** layers. Engineers usually teach a **five-layer** cut, and that is the cut this track uses. The extra split is Physical versus Data Link at the bottom. At the top, OSI’s Session + Presentation + Application collapse into one **Application** layer — which everyone still calls **Layer 7**, not Layer 5. OSI vocabulary won the hallway.

| OSI | Four-layer TCP/IP | Five-layer (this track) | Examples |
| --- | --- | --- | --- |
| Application, Presentation, Session | Application | Application (Layer 7) | HTTP, HTTPS, FTP, SSH |
| Transport | Transport | Transport (Layer 4) | TCP, UDP |
| Network | Internet | Network (Layer 3) | IPv4, IPv6 |
| Data Link | Link | Data Link (Layer 2) | Ethernet, 802.11 |
| Physical | Link | Physical (Layer 1) | copper, fiber, radio |

The rows are **cousins**, not copies. Two independent models that happen to rhyme.

## What each layer is for

The goal is always the same: an **application** on one host talking to an **application** on another. Example: Chrome on PC1 asking the web server on SRV1 for a page.

### Layer 1 — Physical

How a **series of bits** leaves one box and arrives at the next: voltage on copper, light in glass, radio in the air. Chapter 2’s cables live here. Ethernet and Wi-Fi both write Physical rules (connectors, encoding, frequencies) and also Data Link rules.

### Layer 2 — Data Link

Prepare the bits for **this** medium and get them to the **next node** toward the destination. That next node might be the last host or the next **router**. One such step is a **hop**. Layer 2 is **hop-to-hop**.

The address is a **MAC address** on a port. PC1 aims the first frame at R1’s MAC. R1 builds a new frame aimed at R2. R2 builds a new frame aimed at SRV1.

<LessonFigure src="/img/ccna/fig-4-2.png" alt="Layer 2 is hop-to-hop: PC1→R1, R1→R2, R2→SRV1. The switches are not hops." caption="Figure 4.2 — Layer 2 is hop-to-hop: PC1→R1, R1→R2, R2→SRV1. The switches are not hops." maxWidth={600} />

A **switch** in the middle of a LAN is **not** a hop on this count. It is how many end hosts share the LAN (chapter 1). Why a frame can cross a switch without “using up” a hop is a later switching chapter.

Hostnames in the diagrams: **PC1**, **SW1**, **R1**, **SRV1** — PC, switch, router, server.

### Layer 3 — Network

Someone still has to name the **final host**. That is **end-to-end** delivery. The address is an **IP address**.

The destination **IP stays** SRV1 on every hop. The destination **MAC changes** every hop. Those two sentences are the exam-shaped version of “Layers 2 and 3 work together.”

<LessonFigure src="/img/ccna/fig-4-3.png" alt="Layer 3 is end-to-end: the destination IP stays SRV1 while the destination MAC changes each hop." caption="Figure 4.3 — Layer 3 is end-to-end: the destination IP stays SRV1 while the destination MAC changes each hop." maxWidth={600} />

Two IP versions are in play: **IPv4** (`192.0.2.10`) and **IPv6** (`2001:db8::10`). IPv4 ran the world for a long time; IPv6 is how we keep numbering hosts after IPv4’s pool got tight. Both are later chapters. Here, only: Layer 3 uses IP, and the dest IP does not get rewritten the way MAC does.

### Layer 4 — Transport

The packet has reached SRV1. SRV1 is running several **processes**: DNS, HTTP, HTTPS, maybe more. Layer 4 names **which process** with a **port number**.

Port 53 is DNS. Port 80 is HTTP. Port 443 is HTTPS. PC1 puts **443** in the Layer 4 header so the page request does not land in the name server.

<LessonFigure src="/img/ccna/fig-4-4.png" alt="Layer 4 picks the process: PC1 sends to port 443 of the ports SRV1 has open (53, 80, 443)." caption="Figure 4.4 — Layer 4 picks the process: PC1 sends to port 443 of the ports SRV1 has open (53, 80, 443)." maxWidth={600} />

This is **not** the physical jack on the switch. Same English word, different layer.

The two Layer 4 workhorses:

- **TCP** — checks that pieces arrived; HTTP and HTTPS ride it.
- **UDP** — send and do not wait; live voice and some video prefer that.

Details are a later chapter. Here: Layer 4 = application-to-application, via port numbers.

### Layer 7 — Application

The **interface between a program and the network**. HTTPS is not Chrome, and it is not “the website.” It is the protocol the browser uses to ask for a page. Layers 4, 3, 2, and 1 then have something they can deliver.

Walk-through for “please send the page”:

1. **L7** — browser uses HTTPS to write the request.
2. **L4** — destination port 443, so SRV1’s web service gets it.
3. **L3** — destination IP = SRV1, unchanged the whole way.
4. **L2** — destination MAC = next hop, rewritten at each router.
5. **L1** — bits on the medium.

**Forward** means “send to the next node toward the destination” — the last host or the next router. How routers and switches decide that is later.

## Encapsulation and de-encapsulation

A sending host does not throw raw application bytes on the cable. It **wraps** them.

A **header** is extra bytes **in front**: this protocol’s addresses and flags. A **trailer** is extra bytes **at the back**. Ethernet’s trailer carries a check (FCS) so the receiver can notice a message that EMI chewed on.

**Encapsulation** on the sender, top down:

1. Layer 7 prepares data.
2. Layer 4 adds a header to a **port**.
3. Layer 3 adds a header to the destination **IP**.
4. Layer 2 adds a header to the next-hop **MAC** and a **trailer**.
5. Layer 1 sends the bits.

<LessonFigure src="/img/ccna/fig-4-5.png" alt="Encapsulation, top down: data, then L4, L3, and L2 header + trailer, then bits." caption="Figure 4.5 — Encapsulation, top down: data, then L4, L3, and L2 header + trailer, then bits." maxWidth={560} />

The Layer 2 header is the **first** thing on the wire; the trailer is the **last**.

**De-encapsulation** on the receiver is the mirror: take the frame off the medium, inspect and strip L2, inspect and strip L3, inspect and strip L4, hand the data to the application.

<LessonFigure src="/img/ccna/fig-4-6.png" alt="De-encapsulation, bottom up: bits in, strip L2, L3, L4, hand data to the app." caption="Figure 4.6 — De-encapsulation, bottom up: bits in, strip L2, L3, L4, hand data to the app." maxWidth={560} />

### What to call the bundle

| You have just added | Name | Also called | Payload inside |
| --- | --- | --- | --- |
| L4 header | **segment** | L4PDU | application data |
| L3 header | **packet** | L3PDU | a segment |
| L2 header + trailer | **frame** | L2PDU | a packet |

<LessonFigure src="/img/ccna/fig-4-7.png" alt="Segment (L4PDU), packet (L3PDU), frame (L2PDU) — and the payload of each." caption="Figure 4.7 — Segment (L4PDU), packet (L3PDU), frame (L2PDU) — and the payload of each." maxWidth={420} />

**PDU** = protocol data unit. **Payload** = whatever that layer is carrying. A frame’s payload is a packet; a packet’s payload is a segment.

### Adjacent-layer and same-layer

On **one** host, each layer does a favor for the layer **above** it. That is **adjacent-layer interaction**:

- L4 gets L7’s data to the right process.
- L3 gets L4’s segment to the right host.
- L2 gets L3’s packet to the next hop.
- L1 gives L2 a medium for the frame.

Between **two** hosts, a layer talks to the **same** layer on the far side. That is **same-layer interaction**: PC1’s Layer 3 is addressing SRV1’s Layer 3; the L2 header is aimed at the next hop’s Layer 2; bits leave one Physical port and enter another.

<LessonFigure src="/img/ccna/fig-4-8.png" alt="Adjacent-layer interaction inside a host; same-layer interaction between hosts." caption="Figure 4.8 — Adjacent-layer interaction inside a host; same-layer interaction between hosts." maxWidth={420} />

## How to send a page request

1. Write the **application** bytes (HTTPS).
2. Wrap a **Layer 4** header to the destination **port**.
3. Wrap a **Layer 3** header to the destination **IP**.
4. Wrap a **Layer 2** header to the next-hop **MAC**, plus a trailer.
5. Put the **frame** on the **physical** medium.

On the way, routers **forward**: new L2 header, same L3 destination. At SRV1 the wraps come off in reverse.

## Summary

| Idea | Meaning |
| --- | --- |
| Protocol | Shared rules for talking |
| Model | Layered job list so protocols can stay modular |
| OSI | Seven named layers; still the hallway vocabulary |
| TCP/IP (5-layer) | Physical, Data Link, Network, Transport, Application (called Layer 7) |
| L1 | Bits on a medium |
| L2 | Hop-to-hop; MAC; switch ≠ hop |
| L3 | End-to-end; IP; dest IP stays |
| L4 | Process-to-process; port numbers; TCP or UDP |
| L7 | App ↔ network (HTTPS is a protocol, not the browser) |
| Encapsulate | Add L4, L3, L2 header/trailer, then send bits |
| De-encapsulate | Inspect and strip L2, L3, L4, then give data to the app |
| Segment / packet / frame | L4PDU / L3PDU / L2PDU |
| Payload | What a PDU is carrying |
| Adjacent-layer | Lower layer serves the layer above, same host |
| Same-layer | This layer on host A talks to this layer on host B |
