# Router and Switch Interfaces

People say **port** and **interface** as if they were twins. A useful split: **port** is the plastic hole; **interface** is the IOS object (`interface g0/1`). Cisco docs mix them. This lesson says *port* for the connector and *interface* for the config, except where the industry has already picked a winner.

<RouterSwitchInterfacesSimulator />

Set both ends of **Gi0/1**. `a-full` / `a-1000` means autoneg chose it. Hard-set only one end and watch a **duplex mismatch** stay **up/up**. Hard-set two different speeds and the line goes **down/down**. **Burst traffic** only counts when the mismatch is duplex.

## Two defaults you will mix up

Router interfaces start **shutdown**. You already typed `no shutdown` to give them an address.

Switch interfaces start **enabled**. That is how a switch can be **plug-and-play**: cable a PC, frames flow, no config. An **unmanaged** switch is that idea as a product. The CCNA is about **managed** switches — you *can* configure them, and in a real campus you will.

Security habit: **`shutdown` unused switch ports.** An empty jack is an invitation.

Switches do **not** need IPv4 on each access port to forward frames. Addressing a switch (SVI, later) is for *managing* the box, not for MAC learning.

## Description, and `interface range`

```text
SW1(config)# interface range f0/1-2
SW1(config-if)# description access PCs
SW1(config-if)# interface g0/1
SW1(config-if)# description to R1
SW1(config-if)# interface range f0/3-8, g0/2
SW1(config-if)# description unused
SW1(config-if)# shutdown
```

`interface range type slot/first-last` paints many ports at once. Mix types with a **comma**: `f0/3-8, g0/2`. The prompt still says `config-if`; it does not list which members you are in. Read the last `range` twice.

`description` is optional and worth it. Some labs wrap the string in `##` so it pops in a wall of output. The hashes are not syntax.

<LessonFigure src="/img/ccna/fig-8-1.png" alt="Interface config on R1 and SW1: description, speed, and duplex, plus interface range and shutting down unused ports." caption="Figure 8.1 — Interface config on R1 and SW1: description, speed, and duplex, plus interface range and shutting down unused ports." maxWidth={600} />

Verify:

- `show interfaces description` — Status (L1) and Protocol (L2) plus the string. Works on routers and switches.
- `show interfaces status` — **switches only**. Name, connected/notconnect/disabled, VLAN, Duplex, Speed, Type.

`show running-config interface g0/1` (or `show running-config | section interface`) is the typed config. **Defaults are often hidden.** `speed auto` and `duplex auto` will not appear even though they are on.

## Speed

**Speed** is the bit rate the interface will try to run, in Mbps. A FastEthernet jack is usually **10/100**. A GigabitEthernet jack is usually **10/100/1000**. You want the fastest both ends share. If the neighbor is an old 100 Mbps NIC, the Gigabit side must step down.

```text
SW1(config-if)# speed {10 | 100 | 1000 | auto}
```

Curly braces in a command write-up mean **pick one**. Default is **`auto`**. Leave it on for PCs — you will not walk every desk. Some engineers hard-set **both** ends of a router–switch link. If you hard-set only one end, keep reading.

`show interfaces status`: `a-100` means autoneg picked 100. Bare `1000` means someone typed `speed 1000`.

## Duplex

- **Half duplex** — send **or** receive, not both. Wi-Fi is the everyday example (later volume). A **hub** forces half duplex on a wire.
- **Full duplex** — send **and** receive at once. Every modern switched Ethernet port.
- **Simplex** — one direction only (keyboard → PC). Not an Ethernet mode.

```text
SW1(config-if)# duplex {auto | full | half}
```

Default **`auto`**. In a wired campus you expect **full**. You still have to *know* half duplex, because that is how mismatches and leftover hubs show up.

`a-full` = autoneg chose full. `full` = you typed `duplex full`.

## Hubs, collision domains, CSMA/CD

A **hub** is Layer 1: electrical **repeat**. No MAC table, **no buffer**. Two frames arriving together leave as noise. That noise is a **collision**. Every device on the hub sits in **one collision domain**. Only one talker at a time.

<LessonFigure src="/img/ccna/fig-8-2.png" alt="Four PCs on a hub: one collision domain, so two senders at once collide." caption="Figure 8.2 — Four PCs on a hub: one collision domain, so two senders at once collide." maxWidth={480} />

A **switch** stores frames and sends them in order. **Each port is its own collision domain.** Full duplex is legal. Collisions on a switched port are a **bug**, not a tax.

<LessonFigure src="/img/ccna/fig-8-3.png" alt="Four PCs on a switch: each port is its own collision domain, so frames are buffered instead of colliding." caption="Figure 8.3 — Four PCs on a switch: each port is its own collision domain, so frames are buffered instead of colliding." maxWidth={480} />

Exam 1.3.b wording:

- Hub (or the old shared coax): **Ethernet shared media**. Take turns.
- Switch port to one host: **point-to-point**. No sharing.

**CSMA/CD** is how half-duplex Ethernet survives a shared medium:

1. **Carrier-sense** — listen before you talk.
2. **Multiple access** — more than one station uses the medium.
3. **Collision detection** — if you hear a smash, send a **jam**, wait a **random backoff**, try again.

Collisions that matter for CSMA/CD happen in the first **64 bytes**. A collision **after** that is a **late collision** — usually “this side is half duplex and the other side is still talking.”

## Autonegotiation

Both ends **advertise** what they can do and pick the **best common** mode. Faster beats slower. Full beats half.

| Priority | Mode |
| --- | --- |
| 1 | 10 Gbps full (no half at 10G+) |
| 2 | 1 Gbps full |
| 3 | 100 Mbps full |
| 4 | 100 Mbps half |
| 5 | 10 Mbps full |
| 6 | 10 Mbps half |

1 Gbps half exists in the wild and is basically extinct; Cisco will not let you configure it.

<LessonFigure src="/img/ccna/fig-8-4.png" alt="Autonegotiation: R1 and SW1 advertise what they support and settle on the best shared mode, 100 Mbps full duplex." caption="Figure 8.4 — Autonegotiation: R1 and SW1 advertise what they support and settle on the best shared mode, 100 Mbps full duplex." maxWidth={560} />

**Both auto:** a Gigabit router on a Gigabit switch becomes **1000/full** (`a-1000`, `a-full`). A Gigabit router on a FastEthernet switch port becomes **100/full**.

**Only one side auto** — memorize this:

- **Speed:** try to **sense** the neighbor. If that fails, use your **slowest** speed (10 on a 10/100/1000).
- **Duplex:** if the speed you landed on is **10 or 100 → half**. If it is **1000 or more → full**.

Classic trap: neighbor is `speed 100` `duplex full`. Auto side senses 100, then chooses **half**. Link is **up/up**. Performance falls over. That is a **duplex mismatch**, not a down interface.

<LessonFigure src="/img/ccna/fig-8-5.png" alt="Only R1 autonegotiates: it senses 100 Mbps but falls back to half duplex, mismatching SW1’s full duplex." caption="Figure 8.5 — Only R1 autonegotiates: it senses 100 Mbps but falls back to half duplex, mismatching SW1’s full duplex." maxWidth={560} />

## When the counters move

`show interfaces` (or `show interfaces f0/1`) keeps counters. Know these names:

| Counter | Meaning |
| --- | --- |
| **Runts** | Frame &lt; 64 bytes (should have been padded). Collisions can make them. |
| **Giants** | Payload bigger than MTU (usually 1500). Often mixed MTU configs. |
| **Input errors** | All receive errors rolled up. |
| **CRC** | FCS failed. EMI, bad cable, or a jam leftover. |
| **Output errors** | All transmit errors rolled up. |
| **Collisions** | Smash while *this* device was sending. Expected on a hub. Should stay 0 on a switch. |
| **Late collision** | Smash after byte 64. Think duplex mismatch, not a healthy hub. |

### Speed mismatch

Different hard-set speeds (`100` vs `1000`). Both ends **down/down** on `show ip interface brief`. No traffic. Fix the typing.

<LessonFigure src="/img/ccna/fig-8-6.png" alt="Hard-set speeds that differ (1000 vs 100): both interfaces go down/down." caption="Figure 8.6 — Hard-set speeds that differ (1000 vs 100): both interfaces go down/down." maxWidth={560} />

### Duplex mismatch

One half, one full. Both ends **up/up**. The half-duplex side **false-collides** when the full-duplex side talks (the copper can actually carry both directions; CSMA/CD just does not believe it). Half-duplex counters: **collisions**, **late collisions**. Full-duplex counters: **runts**, **CRC** (it received the jam wreckage).
