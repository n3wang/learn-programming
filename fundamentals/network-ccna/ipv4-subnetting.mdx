# Subnetting IPv4 Networks

Classful addressing was simple and wasteful. A class C LAN has **254** usable addresses — too many for a dozen PCs, too few for a campus, so the next step was a whole class B (**65,534**). Class A is millions. The 1981 rules in RFC 791 did not imagine that many networks.

**Classless Inter-Domain Routing (CIDR)** (1993, said “cider”) drops the “prefix must be 8, 16, or 24” rule. The cut can sit **inside** an octet: `/23`, `/26`, `/28`. `/X` is **CIDR notation**. IOS still wants a **subnet mask** (same bits as a netmask) on `ip address` and `ip route`.

An **address block** is a range you are allowed to use, written as its network address and prefix — `192.168.1.0/24` is `.0` through `.255`. **Subnetting** is carving that block into smaller **subnets**. Each extra prefix bit **doubles** the number of subnets and **halves** the addresses in each one.

<Ipv4SubnettingSimulator />

Grey bits are the original network — you cannot change them. Blue bits are **borrowed** from the host half. Empty bits are still host. Click a bar, read the five attributes. **VLSM** on `10.89.100.0/24` packs 122, 59, 30, 11, then 2 hosts.

## Why the old sizes fail

| Classful block | Usable hosts | Typical mismatch |
| --- | --- | --- |
| Class C `/24` | 254 | Home or small office needs dozens |
| Class B `/16` | 65,534 | One campus rarely needs that many on **one** LAN |
| Class A `/8` | 16,777,214 | Never one broadcast domain |

You still **identify** class from the first octet on the exam. You do **not** have to *use* the classful prefix when you subnet.

## Borrow bits (FLSM)

The original network bits stay put. Host bits are yours. To make subnets you **borrow** some host bits and treat them as extra network bits. Flip those borrowed bits through every binary value.

`192.168.1.0/24`, borrow **1**:

- Borrowed bit `0` → **`192.168.1.0/25`** (`.0`–`.127`)
- Borrowed bit `1` → **`192.168.1.128/25`** (`.128`–`.255`)

<LessonFigure src="/img/ccna/fig-11-2.png" alt="Borrow 1 host bit: two /25 subnets, .0 and .128." caption="Figure 11.2 — Borrow 1 host bit: two /25 subnets, .0 and .128." maxWidth={560} />

The network address no longer has to end in `.0`. `.128` is a perfectly legal network address once the cut is mid-octet.

Borrow **2** from the same `/24` → `2^2 = 4` subnets of `/26`:

`.0` / `.64` / `.128` / `.192`

<LessonFigure src="/img/ccna/fig-11-3.png" alt="Borrow 2 host bits: four /26 subnets, .0, .64, .128, and .192." caption="Figure 11.3 — Borrow 2 host bits: four /26 subnets, .0, .64, .128, and .192." maxWidth={560} />

Count the borrowed bits in binary: `00`, `01`, `10`, `11`. Same counting you already did in chapter 6, two digits only.

Number of equal subnets: **`2^x`**, where *x* is **borrowed bits**. You often cannot hit an exact count — 2,000 subnets needs **11** bits (`2^11 = 2048`). Ten bits is only 1,024. Extra subnets are spare capacity, not a bug.

**Fixed-Length Subnet Masking (FLSM)** = every subnet the same size. Real designs usually want **VLSM** (later). FLSM is the exam stepping stone and still shows up as “carve this block into *n* equal pieces.”

## Five attributes, still

Same five numbers as a classful LAN. The only change: **borrowed bits are network**, so “host portion all 0 / all 1” starts **after** them.

- **Network** — first address; host bits all **0**.
- **Broadcast** — last address; host bits all **1**.
- **First usable** — network **+ 1**.
- **Last usable** — broadcast **− 1**.
- **Maximum hosts** — `2^y − 2`, *y* = remaining host bits. Subtract network and broadcast.

Example: **`192.168.1.64/26`**. Prefix 26 → 6 host bits.

| Attribute | Value |
| --- | --- |
| Network | 192.168.1.64 |
| Broadcast | 192.168.1.127 |
| First usable | 192.168.1.65 |
| Last usable | 192.168.1.126 |
| Hosts | `2^6 − 2 = 62` |

<LessonFigure src="/img/ccna/fig-11-4.png" alt="The five attributes of 192.168.1.64/26: network, broadcast, first and last usable, and 62 max hosts." caption="Figure 11.4 — The five attributes of 192.168.1.64/26: network, broadcast, first and last usable, and 62 max hosts." maxWidth={560} />

Exam staple: *PC is `172.16.20.27/28`. Network address?*

1. Last octet `27` = `00011011`.
2. `/28` → last **4** bits are host. Force them to `0000` → `00010000` = **16**.
3. **`172.16.20.16`**.

Do the same with all 1s for broadcast (`00011111` = 31). Usable `.17`–`.30`.

`/16` and `/8` blocks use the **same** arithmetic. Borrow 2 from `192.168.0.0/16` → four `/18`s: `192.168.0.0`, `.64.0`, `.128.0`, `.192.0`. Host bits can span two octets; dotted decimal is only for humans. `10.0.0.0/8` borrow 12 → 4,096 `/20`s. You will not write them all. You **will** be asked for the first, the last, or “how many hosts in each.”

## Masks you will type

IOS does not take `/25` on `ip address`. It takes **255.255.255.128**. One contiguous run of 1s, then 0s.

| Prefix | Mask | Usable hosts |
| --- | --- | --- |
| /24 | 255.255.255.0 | 254 |
| /25 | 255.255.255.128 | 126 |
| /26 | 255.255.255.192 | 62 |
| /27 | 255.255.255.224 | 30 |
| /28 | 255.255.255.240 | 14 |
| /29 | 255.255.255.248 | 6 |
| /30 | 255.255.255.252 | 2 |
| /31 | 255.255.255.254 | 2 (P2P exception) |
| /32 | 255.255.255.255 | 1 (a host route, rarely on an interface) |

The third-octet cousins for `/16` blocks: `/17` → `255.255.128.0`, `/18` → `255.255.192.0`, … `/24` → `255.255.255.0`. Same 128, 192, 224, 240, 248, 252 pattern, just one octet left.

### `/30` and `/31` on a point-to-point link

Two routers, two addresses. **`/30`** still has a network and a broadcast (four addresses total, two usable). **`/31`** (RFC 3021) spends **only** those two addresses — no net/bcast. IOS warns: use `/31` on a non-P2P interface cautiously. `/30` remains the more common lab choice. `/32` on an interface is an OSPF later exception, not a LAN.

## FLSM walk

Block **`172.25.190.0/23`**. Need **four** equal LANs on R1 G0/0–G0/3.

<LessonFigure src="/img/ccna/fig-11-9.png" alt="FLSM scenario: split 172.25.190.0/23 into four subnets for R1’s four LANs." caption="Figure 11.9 — FLSM scenario: split 172.25.190.0/23 into four subnets for R1’s four LANs." maxWidth={480} />

- `2^x ≥ 4` → borrow **2**. New prefix **`/25`**. Mask **`255.255.255.128`**.
- Host bits left: 7 → **126** usable each.
- Borrowed bits count `00` `01` `10` `11` in the last nine host bits of the `/23`:

`172.25.190.0/25`, `172.25.190.128/25`, `172.25.191.0/25`, `172.25.191.128/25`.

<LessonFigure src="/img/ccna/fig-11-10.png" alt="The four /25 subnets of 172.25.190.0/23 — the borrowed bits cross an octet boundary." caption="Figure 11.10 — The four /25 subnets of 172.25.190.0/23 — the borrowed bits cross an octet boundary." maxWidth={560} />

First usable on each interface: **`.190.1`**, **`.190.129`**, **`.191.1`**, **`.191.129`**.

```text
R1(config-if)# ip address 172.25.190.1 255.255.255.128
```

Second text drill: block `10.224.0.0/11`, need **2,000** subnets. `2^11 = 2048` (ten bits is 1024 — not enough). Prefix **`/22`**. Host bits left: 10 → **1022** usable.

<LessonFigure src="/img/ccna/fig-11-11.png" alt="Borrow 11 bits from 10.224.0.0/11: 2,048 /22 subnets." caption="Figure 11.11 — Borrow 11 bits from 10.224.0.0/11: 2,048 /22 subnets." maxWidth={560} />

## VLSM — different sizes, largest first

**Variable-Length Subnet Masking** assigns each LAN only the prefix it needs. FLSM would either starve Toronto (122 hosts) or throw away most of a `/25` on a two-address WAN.

Recipe:

1. Sort needs **largest → smallest**.
2. Smallest prefix with `2^y − 2` covering that need.
3. Place it at the **start of what is left** (aligned on its size).
4. Next network address = **this broadcast + 1**.
5. Repeat.

On the exam, pick the **tightest** fit. In a real net, leave headroom for growth.

<LessonFigure src="/img/ccna/fig-11-12.png" alt="VLSM scenario: two LANs in Toronto, two in Tokyo, and a WAN link, all from 10.89.100.0/24." caption="Figure 11.12 — VLSM scenario: two LANs in Toronto, two in Tokyo, and a WAN link, all from 10.89.100.0/24." maxWidth={600} />

Block **`10.89.100.0/24`** (254 usable). Needs 122 + 59 + 30 + 11 + 2 = 226 — it fits if we mix sizes.

| Order | Need | Prefix | Subnet | Usable |
| --- | --- | --- | --- | --- |
| Toronto A | 122 | /25 (126) | 10.89.100.0/25 | .1–.126 |
| Tokyo A | 59 | /26 (62) | 10.89.100.128/26 | .129–.190 |
| Toronto B | 30 | /27 (30) | 10.89.100.192/27 | .193–.222 |
| Tokyo B | 11 | /28 (14) | 10.89.100.224/28 | .225–.238 |
| WAN | 2 | /30 (2) | 10.89.100.240/30 | .241–.242 |

Leftover `.244`–`.255`. A `/31` WAN would save two more addresses; `/30` is the usual exam pick unless the question asks for most efficient.

Router addresses **count** in the host total. “End host” still means PC/server when you need to distinguish them from R1.

## Exam shapes

- Mask pairs: `/29` = **255.255.255.248**, `/18` = **255.255.192.0**. `/25` is **128**, not 192.
- Drag a prefix to its usable range: find first usable and last usable of **that** prefix, not a neighbor with a different length. `10.23.24.128/25` is `.129`–`.254`. The `/27` at the same `.128` is only `.129`–`.158`.
- Practice sites may hide the original block. If they give `172.26.0.0 255.255.252.0` and ask “how many subnets,” treat the **classful** size as the block (here class B → `/16`, then `/22` is 6 borrowed bits → 64 subnets, 1022 hosts). Skip **wildcard mask** items until ACLs / OSPF.

Do not learn a “magic number” that hides the bits. Binary gets fast. It also feeds every later topic that still uses masks.
