# Network Devices

A railway system, a set of blood vessels, and a group of colleagues are all “networks” in ordinary speech: they connect things. A **computer network** is the same idea for computers. A phone on 5G, a TV streaming a show, a laptop at home, a camera writing footage to disk, and a company file store all count — they are computers that share something over a link.

Short definition: a computer network is a telecommunications network that lets **nodes** share **resources**.

- A **node** is anything attached to the network. That includes the laptop and the phone, and also the infrastructure boxes — switches, routers, firewalls — that make the sharing possible.
- A **resource** is whatever those nodes share. A webpage is a resource. So is a printer on the office LAN, a game lobby, or a mailbox in the cloud.

## LAN and WAN

Look at two offices that reach each other through the public internet.

Each office is a **local area network (LAN)**: devices that share a limited place, such as one floor. The path between offices is a **wide area network (WAN)**: a network that spans cities or farther. The internet is one WAN option among several; later chapters treat other WAN types. Diagrams often draw the unknown middle as a **cloud** — “this is a network, but the inside is not the point of the picture.”

## Clients and servers

The nodes that actually share resources come in a pair.

A **client** uses a service. A **server** offers that service. Neither word is a chassis type. A bulky rack machine can be a server when it streams video to thousands of watchers, and a cheap PC can be a server when it hands a movie file to the PC next to it. Reverse the copy, and the roles swap. Both PCs are clients again when they open a public website.

Useful pairs:

| Client | Server |
| --- | --- |
| A TV asking for a film | The studio’s machine that stores and sends the film |
| A phone scrolling a feed | The hosts that store posts and return them |
| A desktop opening a spreadsheet | The office machine that keeps internal files |

<LessonFigure src="/img/ccna/fig-2-2.png" alt="The usual icons: a desktop for a client, a tower for a server." caption="Figure 2.2 — The usual icons: a desktop for a client, a tower for a server." maxWidth={420} />

<LessonFigure src="/img/ccna/fig-2-3.png" alt="Two desktop PCs sharing a file. The one that sends the file is the server." caption="Figure 2.3 — Two desktop PCs sharing a file. The one that sends the file is the server." maxWidth={420} />

When two PCs share a file, diagrams still often draw both with the “desktop” icon. The icon says *what the box looks like*; the role says *who asked and who answered*.

Client and server nodes are also called **endpoints** or **end hosts**: they talk *over* the network. Switches, routers, and firewalls are the infrastructure that lets them talk.

:::note Role, not hardware
“Server” in a catalog can mean a powerful computer built to serve many clients. For this chapter, treat **server** as a job. Almost any node can take that job for a moment.
:::

## Switches

Hook several end hosts to one **switch** and they can reach each other through that switch. They are not usually talking *to* the switch; the switch is the floor they walk on.

A switch’s job is connectivity **inside a LAN**. Desktops, cameras, printers, and local servers in one office commonly hang off one or more switches. That is why a switch often has many **ports** — physical sockets, often 24 to 48 — for those cables. **Port** and **interface** are used interchangeably: the connector is how this device meets the rest of the network.

<LessonFigure src="/img/ccna/fig-2-4.png" alt="Three end hosts reaching each other through one switch." caption="Figure 2.4 — Three end hosts reaching each other through one switch." maxWidth={480} />

A switch is the wrong box to hang directly on the internet. Crossing from one LAN to another, or from a LAN to an outside network, is a different job.

## Routers

A **router** sits at the **edge of a LAN** and joins that LAN to something outside: another LAN, or the internet. It is not there to give every desk a port. The usual picture is: many hosts on a switch, the switch uplinked toward a router, the router facing out.

<LessonFigure src="/img/ccna/fig-2-5.png" alt="Each LAN reaches the internet through a router at its edge." caption="Figure 2.5 — Each LAN reaches the internet through a router at its edge." maxWidth={640} />

How a router chooses a path is a later chapter (IP addresses start that story). Here, only the placement matters: **inside the LAN = switch; between networks = router**.

### The box sold as a “wireless router”

The Wi-Fi box in a home is rarely “just a router.” It is a small appliance that usually combines **router + switch + wireless access point + firewall**. That mix is fine for a **small office / home office (SOHO)** with a handful of users. An enterprise cannot put every role on one toy box; the jobs split onto separate devices you can scale and manage.

## Firewalls

Opening a LAN to the internet also opens it to whoever else is on that public network. A **firewall** is the device (or the software) that inspects traffic and **allows or denies** it using a rule set.

Two common shapes:

- A **host-based firewall** runs on one machine (for example the built-in firewall on a PC) and watches only that host’s traffic.
- A **network firewall** is a separate appliance that watches traffic **entering or leaving a whole network**.

CCNA work cares about the network appliance. Security chapters later will add more; most of this track stays on routers and switches.

<LessonFigure src="/img/ccna/fig-2-6.png" alt="Firewalls at each LAN edge: office-to-office traffic passes, the attacker is denied." caption="Figure 2.6 — Firewalls at each LAN edge: office-to-office traffic passes, the attacker is denied." maxWidth={640} />

## How to place the boxes

When you sketch an office:

1. Put **end hosts** (clients and servers) at the bottom of the picture.
2. Attach them to a **switch** so the LAN can talk to itself.
3. Uplink that switch to a **router** at the LAN edge.
4. Put a **network firewall** on the path that faces the WAN or internet.
5. Draw the far side the same way, or hide it in a cloud.

If the story is “desk talks to printer,” you only needed the switch. If the story is “desk talks to the other city,” you needed the router. If the story is “stranger on the internet,” you needed the firewall.

## Summary

| Idea | Meaning |
| --- | --- |
| Computer network | Nodes sharing resources over a telecommunications network |
| Node | Any attached device, including infrastructure |
| Resource | Anything shared: a page, a printer, a mailbox |
| LAN | Interconnected devices in a limited area |
| WAN | A network that spans a large distance |
| Client / server | Roles: consume a service / provide a service |
| End host | A node that communicates *over* the network |
| Switch | Forwards among devices in one LAN; many ports |
| Router | Connects a LAN to other networks |
| SOHO / home router | One box doing router, switch, Wi-Fi, and firewall |
| Network firewall | Allows or denies traffic at the network edge by rule |
