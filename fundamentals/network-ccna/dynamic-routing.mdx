# Dynamic Routing

A **routing protocol** is how routers **advertise** prefixes to each other and **build** a table without you typing every `ip route`. **Dynamic** is that process. **Static** is still useful — predictable, exact path — and you can run both on one box.

## Adaptability

A static does not notice that the **path behind** its next hop is dead. If the next hop itself is unreachable, IOS **removes** the route — any kind of route. If the next hop is still up, the row **stays**.

R1 → R2 → R3 → `192.168.30.0/24`. R2–R3 fails. R2 loses the dest (next hop gone) and drops. R1 still has `S via R2`. Black hole. An alternate via R4 sits unused because nobody typed it on R1, and R1 cannot see the cut.

<LessonFigure src="/img/ccna/fig-17-2.png" alt="A static route can’t adapt: the R2–R3 link fails and R1 keeps sending into a dead end." caption="Figure 17.2 — A static route can’t adapt: the R2–R3 link fails and R1 keeps sending into a dead end." maxWidth={600} />

With a protocol, neighbors **withdraw** the dead path and **install** the next-best in seconds. Replace the cable and the old path returns. That is **resilience** statics cannot give you alone.

<LessonFigure src="/img/ccna/fig-17-3.png" alt="With dynamic routing, R2 withdraws the dead route and R1 learns the alternate path via R4." caption="Figure 17.3 — With dynamic routing, R2 withdraws the dead route and R1 learns the alternate path via R4." maxWidth={600} />

Code **D** in the table is **EIGRP** (DUAL). **O** is OSPF. **R** is RIP.

## Scalability

Six routers, a handful of LAN prefixes, two ISP edges: a static to every dest on every router is slow and error-prone. Turn on a protocol and let them advertise.

<LessonFigure src="/img/ccna/fig-17-4.png" alt="A modest network with many subnets — far too many static routes to maintain by hand." caption="Figure 17.4 — A modest network with many subnets — far too many static routes to maintain by hand." maxWidth={560} />

Statics still win when you want **one** path, no surprises. Mix them.

## IGP, EGP, algorithm

**Gateway** is an old word for router (default gateway).

- **IGP** — inside one **autonomous system** (one organization).
- **EGP** — between ASes (enterprise to ISP, ISP to ISP).

<LessonFigure src="/img/ccna/fig-17-5.png" alt="IGPs run inside each autonomous system; an EGP runs between enterprises and ISPs." caption="Figure 17.5 — IGPs run inside each autonomous system; an EGP runs between enterprises and ISPs." maxWidth={600} />

IGP algorithms:

- **Distance-vector** — **RIP** (simple hop count, labs) and **EIGRP** (Cisco-born; RFC 7868 exists, few others implement it). Each neighbor sends “I can reach X with metric N.” You pick the lowest metric. You do **not** own a map past that neighbor. **Routing by rumor.**
- **Link-state** — **OSPF** (exam) and **IS-IS** (providers, skip). Every router floods **link state** (connected prefixes, cost). Everyone builds the same **LSDB** map, then computes a path. More CPU/memory; **areas** (later) split the map.

<LessonFigure src="/img/ccna/fig-17-9.png" alt="Link state: R1 builds a full map of the network and calculates the route itself." caption="Figure 17.9 — Link state: R1 builds a full map of the network and calculates the route itself." maxWidth={560} />

<LessonFigure src="/img/ccna/fig-17-8.png" alt="R1 only knows what R2 and R5 told it; the network behind them is a cloud." caption="Figure 17.8 — R1 only knows what R2 and R5 told it; the network behind them is a cloud." maxWidth={560} />

<LessonFigure src="/img/ccna/fig-17-7.png" alt="Distance vector: each router tells its neighbors “I can reach LAN A, my metric is N.”" caption="Figure 17.7 — Distance vector: each router tells its neighbors “I can reach LAN A, my metric is N.”" maxWidth={600} />

<LessonFigure src="/img/ccna/fig-17-6.png" alt="The five protocols: RIP and EIGRP (distance vector), OSPF and IS-IS (link state), BGP (path vector)." caption="Figure 17.6 — The five protocols: RIP and EIGRP (distance vector), OSPF and IS-IS (link state), BGP (path vector)." maxWidth={560} />

The only common EGP is **BGP**: **path-vector**. The “path” is a list of **ASes**, not a list of routers. Attributes are more than hop count; this exam does not grade BGP math.

<LessonFigure src="/img/ccna/fig-17-10.png" alt="Path vector (BGP): the path is a list of autonomous systems — ISP A, ISP B, Enterprise B." caption="Figure 17.10 — Path vector (BGP): the path is a list of autonomous systems — ISP A, ISP B, Enterprise B." maxWidth={600} />

## Two meanings of “route selection”

1. **Table population** — which learned (or typed) routes **enter** `show ip route`. Not every advertisement is installed.
2. **Packet forwarding** — among rows **already in** the table, which one forwards **this** packet.

A row that is not in the table cannot forward.

Same **destination** means same **network number and prefix length**. `10.0.0.0/8` and `10.0.0.0/16` are two destinations. Both can sit in the table.

## Metric (same protocol)

**Lower is better.** Used only among routes to the **same dest** from the **same** protocol.

| Protocol | Metric |
| --- | --- |
| RIP | Hop count |
| EIGRP | Bandwidth + delay (and knobs). Numbers run large. |
| OSPF | **Cost** from bandwidth, summed along the path |

<LessonFigure src="/img/ccna/fig-17-11.png" alt="Two routes to the same network: R1 installs the one with the lower metric, 2 instead of 3." caption="Figure 17.11 — Two routes to the same network: R1 installs the one with the lower metric, 2 instead of 3." maxWidth={600} />

`show ip route` prints `[AD/metric]`:

```text
O  192.168.3.0/24 [110/2] via 192.168.1.6, 00:08:35, GigabitEthernet0/0
```

Shut the good interface. The cost-4 path replaces it: `[110/4]`.

**ECMP:** same protocol, same dest, **same** metric → **all** of them install (default **four**) and traffic splits.

<LessonFigure src="/img/ccna/fig-17-13.png" alt="ECMP: two OSPF routes with the same cost both go into the table." caption="Figure 17.13 — ECMP: two OSPF routes with the same cost both go into the table." maxWidth={600} />

## Administrative distance (different protocols)

Metrics are not comparable across protocols — kilograms vs kilometers. **AD** is IOS’s **trust** ranking. **Lower** wins.

| Type | Default AD |
| --- | --- |
| Connected | 0 |
| Static | 1 |
| External BGP (eBGP) | 20 |
| EIGRP | 90 |
| OSPF | 110 |
| IS-IS | 115 |
| RIP | 120 |
| Internal BGP (iBGP) | 200 |
| Unusable | 255 |

Connected always wins. **255** means unusable — not installed. Memorize the table.

EIGRP `[90/3584]` vs OSPF `[110/4]` to `10.0.0.0/24`: **D** installs. 3584 vs 4 is noise.

<LessonFigure src="/img/ccna/fig-17-12.png" alt="EIGRP and OSPF both offer 10.0.0.0/24: EIGRP’s lower AD (90 vs 110) wins." caption="Figure 17.12 — EIGRP and OSPF both offer 10.0.0.0/24: EIGRP’s lower AD (90 vs 110) wins." maxWidth={600} />

## Floating static

Default static AD **1** beats every protocol. To hold a static as **backup**, raise its AD **above** the primary protocol (OSPF → **111** or more):

```text
R1(config)# ip route 10.0.0.0 255.255.255.0 192.168.1.2 111
```

OSPF stays `[110/4]`. Kill the OSPF path; `S [111/0]` appears. Static **metric is always 0**.

<LessonFigure src="/img/ccna/fig-17-14.png" alt="A floating static route with AD 111 sits behind the OSPF route as a backup." caption="Figure 17.14 — A floating static route with AD 111 sits behind the OSPF route as a backup." maxWidth={600} />

**Same AD as the protocol still prefers static.** Go **higher**. Use a float toward a neighbor you do **not** peer with, or when you want a known backup path.

## Install vs forward

Learned:

- `203.0.113.0/24` static
- `/25` RIP metric 4
- `/26` EIGRP
- `/27` OSPF

**All four install.** Same number, different lengths → different dests. Overlap on the number line does not matter for install. Longest match is **not** an install rule.

Learned:

- `10.0.0.0/8` EIGRP and OSPF → keep **EIGRP** (AD)
- `10.0.0.0/16` OSPF metric 20 and OSPF metric 5 → keep **metric 5**

**Forwarding** a packet to `203.0.113.65` with those four rows in the table: ignore AD and metric. Keep **matching** routes, then the **longest** prefix.

Last octet only (first 24 bits already match):

- `.0` = `00000000`
- `.65` = `01000001`

`/24` and `/25` match (bit 25 is 0). `/26` and `/27` need bit 26 = 0; `.65` has 1. Winner: **`/25`** via `192.168.1.6`.

<LessonFigure src="/img/ccna/fig-17-15.png" alt="Overlapping routes: 203.0.113.0/24, /25, /26, and /27 each cover a smaller slice." caption="Figure 17.15 — Overlapping routes: 203.0.113.0/24, /25, /26, and /27 each cover a smaller slice." maxWidth={480} />

Exam wording: **most specific matching route**, not “longest prefix” alone (a longer prefix that does not match loses).

## The `network` command

RIP, EIGRP, and OSPF all **activate on interfaces**, then **advertise each interface’s prefix**. The shared knob is **`network`**. This exam wants the **OSPF** form. Areas stay at **0** until the OSPF chapter.

```text
R1(config)# router ospf 1
R1(config-router)# network 192.168.1.0 0.0.0.3 area 0
```

<LessonFigure src="/img/ccna/fig-17-16.png" alt="Activating OSPF with network commands and wildcard masks, one interface at a time." caption="Figure 17.16 — Activating OSPF with network commands and wildcard masks, one interface at a time." maxWidth={560} />

`1` is a **process ID** (multiple processes exist; skip why). Syntax: `network ip-address wildcard-mask area area-id`.

A **wildcard** is 32 bits. **0** = that bit **must match** between the command IP and the interface IP. **1** = don’t care. It **looks** like an inverted mask and is **not** a mask.

<LessonFigure src="/img/ccna/fig-17-17.png" alt="A /30 netmask (255.255.255.252) and its wildcard (0.0.0.3): every bit flipped." caption="Figure 17.17 — A /30 netmask (255.255.255.252) and its wildcard (0.0.0.3): every bit flipped." maxWidth={560} />

Shortcut: each mask octet from **255** is the wildcard octet. `/30` `255.255.255.252` → `0.0.0.3`. `/24` → `0.0.0.255`. `/32` → `0.0.0.0`.

| Prefix | Mask | Wildcard (last octet) |
| --- | --- | --- |
| /24 | 255.255.255.0 | 0.0.0.255 |
| /25 | 255.255.255.128 | 0.0.0.127 |
| /26 | 255.255.255.192 | 0.0.0.63 |
| /27 | 255.255.255.224 | 0.0.0.31 |
| /28 | 255.255.255.240 | 0.0.0.15 |
| /29 | 255.255.255.248 | 0.0.0.7 |
| /30 | 255.255.255.252 | 0.0.0.3 |
| /31 | 255.255.255.254 | 0.0.0.1 |
| /32 | 255.255.255.255 | 0.0.0.0 |

The command IP **need not** be the network address, and the wildcard **need not** equal the interface mask. If the 0-bits match, OSPF starts on that iface.

`network 192.168.1.0 0.0.0.7 area 0` hits `192.168.1.0`–`.7` (G0/0 `.1` and G0/1 `.5`). Advertises **`192.168.1.0/30` and `192.168.1.4/30`**, not a /29.

<LessonFigure src="/img/ccna/fig-17-18.png" alt="One wider network command covers two interfaces; a second covers the third." caption="Figure 17.18 — One wider network command covers two interfaces; a second covers the third." maxWidth={560} />

`network 192.168.2.1 0.0.0.0 area 0` hits only `.1`. Advertises **`192.168.2.0/24`**, not `/32`.

**Habit:** interface IP + **`0.0.0.0`** so you do not arm a surprise iface. Lab-all: `network 0.0.0.0 255.255.255.255 area 0`. Do not do that in production.

Two myths:

1. Wildcard must equal the iface mask — **no**.
2. `network` lists prefixes to advertise — **no**. It lists **interfaces to activate**. The prefix that goes out is the **interface’s** prefix.

The next chapter has `ip ospf 1 area 0` on the interface. You still need `network` and wildcards on the exam.

## Exam shapes

- Static stays after a downstream cut; dynamic withdraws and reroutes.
- IGP/EGP. DV rumor vs LS map. BGP path-vector.
- `[AD/metric]`. Same dest + same protocol → metric (or ECMP). Different protocol → AD.
- AD table. Float = static AD **higher** than the protocol.
- Different lengths = different dests (all install). Forward = **most specific match**.
- `router ospf`, `network` + wildcard: activate ifaces, advertise iface prefixes.
