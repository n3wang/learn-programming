# 0-1 BFS

On an **unweighted** graph, BFS finds single-source shortest paths in `O(|E|)`: distance is just the fewest edges. You can think of that as every edge having weight `1`.

If weights are arbitrary, you need Dijkstra (`O(|V|^2 + |E|)` or `O(|E| log |V|)`).

If **every weight is only `0` or `1`**, you can still solve SSSP in **`O(|E|)`** with a deque. That is 0-1 BFS.

## Why a deque is enough

Look at Dijkstra with a set as the priority queue:

```cpp
d.assign(n, INF);
d[s] = 0;
set<pair<int, int>> q;
q.insert({0, s});
while (!q.empty()) {
    int v = q.begin()->second;
    q.erase(q.begin());

    for (auto edge : adj[v]) {
        int u = edge.first;
        int w = edge.second;
        if (d[v] + w < d[u]) {
            q.erase({d[u], u});
            d[u] = d[v] + w;
            q.insert({d[u], u});
        }
    }
}
```

In a 0-1 graph, vertices sitting in the queue never differ by more than **1** in distance from the source. If `v` is the current vertex, every `u` still in the queue satisfies

`d[v] ≤ d[u] ≤ d[v] + 1`

You only ever insert a vertex at the current distance or at current `+ 1`. A vertex with `d[u] - d[v] > 1` would have had to come from some `t` with `d[t] > d[v]`, which Dijkstra would not process before `v`.

So the queue looks like:

```text
Q =  [ v … u ]   [ m … n ]
       d[v]        d[v]+1
```

A balanced tree is overkill. Use a **deque**:

- Weight **0**: new distance equals `d[v]` → `push_front`
- Weight **1**: new distance equals `d[v] + 1` → `push_back`

The deque stays sorted.

```cpp
vector<int> d(n, INF);
d[s] = 0;
deque<int> q;
q.push_front(s);
while (!q.empty()) {
    int v = q.front();
    q.pop_front();
    for (auto edge : adj[v]) {
        int u = edge.first;
        int w = edge.second;
        if (d[v] + w < d[u]) {
            d[u] = d[v] + w;
            if (w == 1)
                q.push_back(u);
            else
                q.push_front(u);
        }
    }
}
```

## Dial’s algorithm

If every edge weight is an integer `≤ k` (not only 0/1), distances of vertices in the “queue” differ from `d[v]` by at most `k`. Keep **`k + 1` buckets**. When the bucket for the smallest distance is empty, rotate to the next distance. That extension is **Dial’s algorithm**.

<details>
<summary>🧪 Dial’s buckets on weights ≤ 2</summary>

<PistonRunner
  lang="c++"
  height="440px"
  code={`#include <iostream>
#include <vector>
#include <deque>
using namespace std;

const int INF = 1e9;

int main() {
    // 4 nodes; edges with weights in {1,2}
    int n = 4, K = 2;
    vector<vector<pair<int,int>>> adj(n);
    auto add = [&](int a, int b, int w) {
        adj[a].push_back({b, w});
        adj[b].push_back({a, w});
    };
    add(0, 1, 1);
    add(1, 2, 2);
    add(0, 2, 2);
    add(2, 3, 1);

    vector<int> d(n, INF);
    d[0] = 0;
    vector<deque<int>> buckets(K + 1);
    buckets[0].push_back(0);
    int items = 1, cur = 0;

    while (items) {
        while (buckets[cur % (K + 1)].empty()) cur++;
        int v = buckets[cur % (K + 1)].front();
        buckets[cur % (K + 1)].pop_front();
        items--;
        if (cur > d[v]) continue;
        for (auto [u, w] : adj[v]) {
            if (d[v] + w < d[u]) {
                d[u] = d[v] + w;
                buckets[d[u] % (K + 1)].push_back(u);
                items++;
            }
        }
    }
    for (int i = 0; i < n; i++)
        cout << "d[" << i << "] = " << d[i] << endl;
    return 0;
}
`}
/>

</details>

## When to use it

| Graph | Algorithm |
|---|---|
| Unweighted (or all weights `1`) | Normal BFS |
| Weights only `0` and `1` | 0-1 BFS |
| Small integer weights `1 … k` | Dial |
| Arbitrary non-negative weights | Dijkstra |

<Exercise title="Labyrinth" anchor="exercise-labyrinth">

### B. Labyrinth

**Judge:** [Codeforces 1063B — Labyrinth](https://codeforces.com/contest/1063/problem/B)

You are in an `n × m` maze (`.` free, `*` obstacle). Start at row `r`, column `c`. You may move up, down, left, or right into free cells, staying in bounds.

Your keyboard is broken: you may move **left at most `x` times** and **right at most `y` times**. Up and down are unlimited.

How many cells (including the start) are reachable under those limits?

**Constraints:** `1 ≤ n, m ≤ 2000`, `0 ≤ x, y ≤ 10⁹`. The start cell is free.

**Sample 1**

```text
Input
4 5
3 2
1 2
.....
.***.
...**
*....

Output
10
```

Reachable cells marked `+`:

```text
+++..
+***.
+++**
*+++.
```

**Sample 2**

```text
Input
4 4
2 2
0 1
....
..*.
....
....

Output
7
```

```text
.++.
.+*.
.++.
.++.
```

:::tip Why 0-1 BFS?
Treat vertical moves as weight **0** and horizontal moves as weight **1**. From the start, 0-1 BFS finds each cell with a minimum “horizontal budget”; then check whether that path fits within `x` left and `y` right (using the column difference). Naive BFS on `(row, col, left, right)` is too slow for `n, m ≤ 2000`.
:::

</Exercise>

### KATHTHI

**Judge:** [SPOJ KATHTHI](https://www.spoj.com/problems/KATHTHI/)

Kathiresan starts at `(0, 0)` in an `R × C` prison and must reach `(R − 1, C − 1)`. From a cell he may step to any of the four adjacent cells (in bounds).

- If `map[x1][y1] == map[x2][y2]`, the move kills **0** guards.
- If the letters differ, the move kills **1** guard.

Find the **minimum** number of guards to kill to escape.

**Constraints:** `1 ≤ t ≤ 10`, `2 ≤ R, C ≤ 1000`, cells are lowercase letters `a`–`z`.

**Sample**

```text
Input
4
2 2
aa
aa
2 3
abc
def
6 6
akaccc
aaacfc
amdfcc
aokhdd
zyxwdp
zyxwdd
5 5
abbbc
abacc
aaacc
aefci
cdgdd

Output
0
3
2
2
```

:::tip Why 0-1 BFS?
Same letter → edge weight **0**; different letter → weight **1**. Shortest path in that graph is exactly the minimum guards killed. Use a deque: same-letter neighbours `push_front`, different-letter `push_back`.
:::

</Exercise>

### Ocean Currents (UVa 11573)

**Statement:** [UVa 11573 — Ocean Currents (PDF)](https://onlinejudge.org/external/115/11573.pdf)  
**Also mirrored:** [Luogu UVA11573](https://www.luogu.com.cn/problem/UVA11573)

A lake is an `r × c` grid (`≤ 1000`). Each cell holds a digit `0`–`7`: the direction of the current, clockwise from north:

```text
7 0 1
 \|/
6-*-2
 /|\
5 4 3
```

The boat may move one step in any of the **eight** directions, staying in bounds. Going **with** the current costs **0** energy; any other direction costs **1**.

You get up to `n ≤ 50` trips. For each trip `(rs, cs) → (rd, cd)` (1-based), print the minimum energy needed.

**Sample**

```text
Input
5 5
04125
03355
64734
72377
02062
3
4 2 4 2
4 5 1 4
5 3 3 4

Output
0
2
1
```

:::tip Why 0-1 BFS?
From cell `u`, the eight neighbours are edges of weight **0** (matching the current digit) or **1** (any other direction). Run 0-1 BFS once per trip (or reuse carefully); Dijkstra also works but the deque is `O(rc)` per query.
:::

</Exercise>
